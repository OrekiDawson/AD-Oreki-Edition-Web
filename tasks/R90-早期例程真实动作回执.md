# R90：早期例程空转吞掉调度节拍（Web）

## 状态

生产修复与定向测试完成；提交与 Pages 部署见本轮交付记录。

## 根因

`src/game.js` 的 `tryOrekiEarlyRoutine()` 无论有没有真的买到东西都 `return true`（该返回值自 2026-10-29 起存在）。R78 把调度器改成「一次真动作 = 全局节拍 + 同帧唯一名额，no-op 才顺延给下一个任务」之后，这条无条件 true 让 `routine` 每拍都被判定为「已动作」并吃掉整拍。

`runCycle` 的固定顺序是 `breakUpgrades(5) → breakGate(6) → routine(10) → early(20)`，执行层又受 `frameActed` 限制（R88）。因此 `early`（无限维度 / 无限升级）在 `routine` 有返回值时永远轮不到；首次无限之后 ID1 解锁与首次永恒都靠 `early` 推进，这条饿死链会把「首次无限 → 首次永恒」直接卡死。

修复前的夹具结果：第 1 项「空转必须返回 false」失败（实际 true），第 2 项「5 拍内 early 至少执行」失败（实际 0 次）。

## 生产修改

- `src/game.js`
  - `tryOrekiEarlyRoutine()` 在动作前记录快照：反物质余额、`totalTickBought`、`dimBoosts`、`galaxies`、8 层反物质维度数量。
  - 动作后只有任一项发生真实变化才返回 true；全部不变返回 false，让本拍顺延给 `early` 等后续任务。
  - 购买顺序、成本、扣费路径完全不变；不写任何存档字段。
