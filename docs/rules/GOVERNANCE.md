# 规则维护

本文件只规定当前活动规则的新增、修改、冲突处理和同步。历史内容不作为当前执行依据。

## 1. 新增与修改

### 1.1 查重与边界

新增规则前检查核心规则、专项规则和长期证据文档。相同要求修订原位置，不追加平行正文；每条规则明确范围、触发条件、动作、成功判定、例外和失败处理。

### 1.2 用户要求优先

用户明确要求可以替代同级规则；安全、真实性、存档和工作区保护不得被普通效率规则绕过。无法确定冲突时，只暂停受影响路径并报告。

### 1.3 事实与规则分离

动态环境事实、任务状态、PID、哈希和一次性日志放入 `FACTS.md`、任务或报告，不写入常驻规则。

## 2. 编号

### 2.1

活动规则统一使用连续层级编号：一级 `1.`，二级 `1.1`，三级 `1.1.1`。编号只表达当前文档结构，不承担历史任务编号功能。

### 2.2

R 编号、用户日期和提交号只能作为来源标识，不能替代正文层级，也不能据此保留已失效条款。

## 3. 规则同步

### 3.1 Android/Web

Android 与 Web 的同名核心规则应保持一致；平台差异写入对应平台规则或 `WEB_ANDROID_DIFFERENCES.md`，不得在镜像中静默分叉。

### 3.2 四仓库

四个仓库分别维护自己的 README、代码边界和验证证据：Android、Web、frame-observer、`web/_deploy/site`。部署副本不是第二个源码入口。

### 3.3 检查范围

规则维护后检查 Markdown 链接、索引路由、镜像文件和规则编号；只运行链接、编号、同步和冲突检查，不触发无关构建、部署或存档操作。

## 4. README 约束

### 4.1

README 只保留当前有效的用途、使用方式、目录边界、运行/部署入口和交付要求。

### 4.2

README 不是开发流水账、变更日志或任务交接文档；不得出现 R 开头的任务/轮次编号、归档、已废止、失效、旧版本、历史规则或被取代内容，也不得复制规则正文、一次性环境事实或未验证结论。

### 4.3

规则以规则入口为准，事实以 `FACTS.md` 或验证记录为准；README 只提供链接和简要说明。按 GitHub 项目常见标准检查项目定位、目标读者、快速开始、环境前提、用法、目录、贡献、许可证、安全和反馈入口；修改后检查四个仓库 README 的一致性、链接、路径、命令和版本描述。

## 5. 变更边界

### 5.1

规则维护不改变 Android/Web 业务逻辑，不修改存档，不发布 APK，不部署 Pages，也不停止其他已授权开发任务。

### 5.2

规则变更完成后保留用户已有工作区修改；不得强推、硬重置、清理或覆盖其他任务成果。
