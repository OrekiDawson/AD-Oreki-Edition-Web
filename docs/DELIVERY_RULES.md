# Web 开发、移动浏览器验收及 Pages 发布长期增量规则

> 生效日期：2026-11-12。本文件由 [AGENTS.md](../AGENTS.md) 引用，与现行 Web Playwright、DeepSeek 峰谷和真实存档规定一同生效。已归档旧规则只供追溯。

## 1. 项目目标与工作流程

- Android/Web 同步推进，玩家可见 MOD 行为等价；新档真实墙钟不超过 180 分钟通关，减少无意义等待和重复切页，保留有趣手动操作。严禁伪造资源、存档、阶段、挑战完成和成就。
- 新轮开发 Prompt 原样以 `/goal 基于原版https://github.com/IvarK/AntimatterDimensionsSourceCode和/home/oreki/Antimatter+Dimensions_3.21.0_APKPure.xapk制作反物质维度MOD。` 开头。轮内追加/修改不再用 /goal，不重置计时或历史编号；编号由 ChatGPT 按台账决定。Agent 读取当前有效 AGENTS、FACTS、tasks、最新状态及相关源码，Prompt 每轮重申适用规则。
- P0 优先处理崩溃、不可达/错误可达阶段、存档损坏与核心功能失效；P1 处理通关瓶颈、自动化、实时 GUI 与跨端偏差；P2 才是非阻断迁移、体验/代码质量。避免只为凑工作量审计、重构或修改业务代码。
- Web 保持 ACTIVE 且独立开发、独立 CI 和发布；Android APK/AVD 阻断不应阻碍 Web 自身已合格版本上线。Web 上游固定 **2026-07-17 冻结基线** `IvarK/AntimatterDimensionsSourceCode` @ `5409e320`（见第 5 节）；允许只读监测上游安全/重大缺陷，禁止未经用户授权自动升级、自动合并、修改冻结基线或部署；不能因 Android 版本不同就伪称原版行为一致。

## 2. 玩法、界面与定位

- 挑战启动后只能通过原版真实结算链完成；智能购买器阶段感知、手动优先、支持 1–60 秒间隔及总开关，关闭立即停止，不强制恢复玩家已关闭的原版设置、不跨阶段解锁或伪造购买记录。
- UI 对资源、真实阶段、自动操作和玩家配置的改变及时响应；不得依赖切页才触发业务。Web 关闭新闻，主要面向 Android Chrome 默认手机视口，正常移动端可用即可，不强制桌面专项验收。
- 教程保留原版含义，全文简体中文、玩家视角；MOD 专属内容集中附录 F，与 Android 一致。教程 JSON 修改后必须按现有生成脚本同步对应生成模块；生产部署门禁必须严格验证同步，不能因 CI 的历史 advisory 绿灯视为教程同步 PASS。
- Agent 主动采集 Console、pageerror、Playwright Trace、截图、DOM/控件状态、真实存档来复现 Bug 和确定根因，不用遮挡 UI、吞错误或直接写假阶段/资源来骗过测试。

## 3. 真实验收

- 按修改范围运行最小必要 Node/Playwright 测试。涉及阶段、挑战、存档、自动购买器、教程或 GUI 的生产改动，必须在真实 Chromium 移动端上下文验证；重大兼容问题按需补充 AVD/真机 Android Chrome。
- 关键条件做正反极性与阈值边界；与官方原版相同阶段的操作和 GUI 做针对性对比，不要求每轮完整从头跑到结局。Playwright 启动冒烟 PASS 不能代替业务行为 PASS，Node 检查 PASS 不能代替真实浏览器行为 PASS。
- `savestates/` 保存有版本、用途、来源及预期的可复用测试存档，禁止提交隐私/凭据。保护玩家存档、历史状态与已验证结果。结果明确区分 PASS / FAIL / BLOCKED / NOT RUN。

## 4. GitHub、CI/CD 和交付

- GitHub 源码仓 `OrekiDawson/AD-Oreki-Edition-Web` 与 Pages 仓 `OrekiDawson/OrekiDawson.github.io` 职责独立；`web/_deploy/site/` 不能变成第二份功能源码。ChatGPT 管理 Pages 与 CI/CD，Agent 每轮根据实际改动核对 Actions 与部署证据。
- Web main 上的 Node/Playwright CI 与生产部署分离：正式部署必须具备实际移动端验收、教程源/生成物一致、受信任主干 SHA、受控发布 Token 和线上加载核验。CI 绿灯不能自动代表生产已上线，Deploy 失败不等于 Web 版本已发布。
- 成果无论成功或失败均以中文 Commit/Push 保存；普通已验证改动可推 main，高风险、CI/CD、生产部署或未过门禁的改动走分支/PR，CI 合格再合并。禁止强推/丢改动，Push ≠ 生产发布。
- 两小时至少交付一个**合格**稳定版为节奏目标，服从真实验收门禁和现行 DeepSeek 峰谷安全规则；未合格时如实标记超期及阻碍，不能伪报 PASS。Web 验收合格即可部署 oreki.net，无需等待 Android 四渠道。
- 可并行开发独立文件，真实浏览器会话及正式部署采用可追溯的独占控制。维护相关 FACTS/tasks/README/教程与 Android 差异记录，不无差别重写历史文档。授权轮次真正完成后停止，不擅自开启下一轮；高峰或阻碍导致未完成时保留 `blocked/paused`，不得虚报 `complete`。
- **Lead 与高峰优先级（2026-11-14，强制）**：非高峰期 Lead 不得因子 Agent 失败、局部 `BLOCKED`、CI/AVD/PR 冲突擅自停工，应协调或转做其他可执行任务；**DeepSeek 高峰期间 Lead、所有子 Agent、其他模型及自动化开发全部停止**，不得换模型继续开发，也不得启动构建、测试、Git/CI/CD、发布或部署。北京时间工作日 09:00–12:00、14:00–18:00 高峰，08:50/13:50 开始安全收尾并在峰前停止；周末和中国法定节假日按已核实规则低谷。峰前保存代码/证据/恢复点、解除 Goal 激活但不虚报完成，低谷恢复同一轮。细则以本仓 `AGENTS.md` 峰谷章节和实际生效的全局规则为准；该停工要求优先于 Lead 持续推进和两小时交付节奏。


## 5. 上游基线冻结与独立 MOD 版本体系（2026-11-13，用户决定）

> 本节是长期规则，不是 “已完成升级” 或 “已放宽部署门禁” 的声明。历史任务编号、历史报告与历史部署记录不改写。

### 5.1 Web 上游基线正式冻结

- 唯一 Web 基线：`IvarK/AntimatterDimensionsSourceCode` @ `5409e320cecef96a917cca1dfb68f1f183e499ca`（2026-07-17；AD 11.5 / Reality Update）。登记：`docs/SHARED_GAMEPLAY_STANDARD.md`（第 11 行）与 `docs/FACTS.md` 第 6 节。
- **上游监测与自动追新边界**：允许对上游做**只读监测**（安全公告、重大缺陷/崩溃/存档/数据错误、重要修复的公开信息）用于评估选择性移植；**禁止未经用户授权自动升级、自动合并上游代码、修改冻结基线、自动改版本号或自动部署**；完整 Web 基线替换只能在用户明确批准的新轮次进行（见第 5.5–5.7 节）。
- 与 Android 基线独立：Android 固定官方 3.21.0，Web 固定本冻结上游；不要求版本号同源，不得用一端结果冒充另一端验收。

### 5.2 选择性上游移植（默认不跟进）

| 上游变更类型 | 处理 |
| --- | --- |
| 安全修复 | 优先评估移植 |
| 崩溃 / 存档损坏 / 数据错误 | 优先评估移植 |
| 性能改进 | 有实测收益才选择性移植 |
| 重大新玩法 / 机制 | 单独轮次评估；默认不自动跟进，须双端行为等价验收 |
| 普通 UI / 重构 / 混淆 / 纯版本号 | 默认不跟进 |

- 移植必须记录上游仓库/commit/文件/行、本地适配说明与 Playwright 真实浏览器 `PASS`/`FAIL`/`NOT RUN`，禁止整包替换。
- 移植不改变冻结基线的定义，不得把内部版本号或上游 commit 指向新版本。

### 5.3 独立 MOD 版本体系

- 产品版本名 **Oreki Edition**，从 `1.0.0` 起：`1.0.1` = patch、`1.1.0` = 向后兼容增强、`2.0.0` = 重大/不兼容变更。
- Web 部署记录必须绑定：MOD 版本、Web 上游基线 commit `5409e320`、部署源码 commit、构建/部署时间、线上加载核验结果；不得用相同版本号掩盖不同上游基线。
- 部署回滚路径必须保留；不得破坏浏览器存档兼容（旧存档可读）与已部署版本回退能力。
- 历史部署记录与 Git 标签不改写；迁移 versionName/文件名/发布说明时需在实施轮次记录映射（MOD 版本 ↔ 上游基线）。

### 5.4 反混淆 / Kotlin 与双端一致性目标

- Android 反混淆/Kotlin 重建目标固定为 3.21.0 基线；Web 以 `5409e320` 为行为参照，复用 `docs/SHARED_GAMEPLAY_STANDARD.md`、`WEB_ANDROID_DIFFERENCES.md` 与既有测试数据，不因上游发版重置。
- Web 生产修改仍按 Playwright 真实移动端验收；Node 静态检查不能代替行为验收。

### 5.5 完整 Web 上游升级的边界（研究评估 / 用户授权 / 正式发布门禁）

#### 5.5.1 研究评估（无需新授权）

- 允许对上游安全修复、崩溃、存档损坏、数据错误、重要性能修复做**针对性移植调研、最小原型与本地 Playwright 验证**（含只读监测上游公开信息）。
- 研究评估**不修改冻结基线**：不改内部版本号/上游 commit 指向、不整包替换、不改变已部署包名/存档格式。
- 当前冻结版本存在未解决 P0 或构建链未完成，都不构成禁止研究评估的理由；研究评估不得绕过既有 CI/部署门禁。

#### 5.5.2 用户授权（必须）

- **完整 Web 基线替换**（`5409e320` 整体替换）必须在用户明确批准的新轮次进行。
- 仅技术条件满足不能代替用户授权；未经授权不得自动升级、自动合并上游或修改冻结基线。

#### 5.5.3 正式发布门禁（完整升级发布前必须全部满足）

1. 已存在通过门禁的合格稳定版，可完整回退；
2. Web 生产构建/部署链能产出并通过真实移动浏览器验收；
3. 当前基线无未解决 P0（崩溃/存档损坏/核心功能失效）；
4. 存档兼容与部署回滚验证通过（旧存档可读、线上可回退）；
5. Android/Web 玩家可见行为等价验收通过（按 shared 标准记录）；
6. 收益/成本评估支持升级（含教程/生成物/差异文档维护成本）。

### 5.6 记录与禁止

- 冻结基线与选择性移植事实写入 `docs/FACTS.md`；不改历史任务编号、历史报告与历史部署记录。
- 禁止：**未经用户授权的自动追上游/自动合并上游代码**、自动改版本号、未验证整包替换、以“上游已发版”为由跳过正式发布门禁、借基线升级放宽部署或 CI 门禁。允许且鼓励只读监测上游安全与重大缺陷信息用于评估。
- 不为落实本节触发任何构建、部署或上游同步；规则落地与交付解耦。

## 6. PR 规模预警与测试证据分层（2026-11-14，强制）

> 细化 [AGENTS.md](../AGENTS.md) 第 11 节。该治理规则不放宽现有 Node/Playwright、教程生成一致性、Pages 受保护部署或 Android/Web 等价门禁，也不回溯改写 Android PR #43。

### 6.1 单一主目标与规模预警

- Web 玩法与 UI、测试/CI、教程生成、Pages 部署和大批量测试证据原则上各有独立 PR；只有确实无法拆分的原子变更可合并，说明原因、任务来源、依赖与实际验证。
- 任一条件触发 PR 说明义务：文件 >100；新增代码/文本 >20,000 行；新增单个文本数据文件 >5 MB；跨多个独立任务或历史轮次。这些是预警阈值而非禁止线，不因规则对小 PR 增设审批。
- 说明文件/行数按业务代码、配置、生成文件、证据与历史材料分类；特别列出最大文件、来源 SHA、可再生性、重复快照和 Node/Playwright/上线验证真实状态。GitHub 统计的新增行数不能直接等同新业务代码量。

### 6.2 原始证据与保留期

- `reports/` 内保留最小必要的控制台片段、DOM/截图索引、复现步骤、Playwright 视口与浏览器版本、源码 SHA、CI Run ID、最终网页加载核验、PASS/FAIL/BLOCKED/NOT RUN；避免把完整 Console/Trace/录屏、重复截图、可再生构建结果逐次大批量入 Git。
- 大型测试原始证据优先进入受控持久归档；短期执行产物可以放 Actions Artifacts，但不得作为长期唯一副本。长期关键证据应保留可验证的 SHA、可取回路径和合适的持久备份；如使用 Git LFS，须先确认仓库配置、访问权限与 CI 可用性。
- 禁止将密钥、Token、隐私内容和真实个人存档写进公开或私有 Git。证据归档前检查敏感内容；历史数据去重应先核实是否有唯一复现价值，不能靠删除原件减小 PR。

### 6.3 合并与历史边界

- 大 PR 不自动拒绝，也不把静态 Node PASS 当作真实 Playwright 或 Pages DEPLOY PASS；继续按 Required Checks、受保护分支和部署门禁执行，不关闭规则或跳过真实浏览器测试。
- 历史 PR #43 与其他已合并数据不强推、不重写；任何清理都必须先核对证据引用、长期备份可取回与回滚路径，然后通过独立可追溯变更实施。
- Lead 在后续授权轮次自主管理规模和证据，保持快速迭代。本次仅提交长期规则，不修改现有 /goal/计时、Web 冻结上游、教程、构建或 Pages 生产部署。
## 7. CI/CD 自主管理与故障自愈（2026-11-14，强制）

- DeepSeek Lead 负责 Web/Pages CI/CD 日常管理与自愈；Actions 独立执行验证；Ruleset/Required Checks/受保护环境不可绕过。Lead 可自主检查与修复工作流、测试、缓存、依赖，创建 PR 并在门禁通过后合并。
- 故障闭环：真实失败日志 → 根因 → 最小修改 → PR → CI 验证 → 合规合并 → 复核 Run；不得删测试/吞异常/改断言；局部 BLOCKED 继续其他工作。
- Web 门禁：Node/单测/Playwright/移动 Chromium/存档与核心机制定向验收 + 源码 SHA 与产物一致；Pages 只经受控工作流部署并核对线上 SHA 与视口行为；禁止手动覆盖 Pages。
- 自动合并仅限：无未解决关键审查问题、Required Checks 全通过、无真实冲突/高风险回归、符合 Ruleset 与权限。自动发布必须经受保护工作流。
- 禁止：削弱规则、跳过检查、强推、密钥入仓库、伪造 CI/部署结果、在 CI 中调用 DeepSeek API。
- 遵守 DeepSeek 峰谷停工；谷时主动检查 CI/部署状态与缓存效率，明确问题优先修复。
