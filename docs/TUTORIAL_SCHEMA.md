# 游戏内教程数据结构（唯一源）

> 本文件定义 `src/core/oreki-tutorial-data.json` 的字段契约。
> 工作区根 `AGENTS.md §24.3` 的「十字段操作手册格式」与本文件一一对应，两处冲突时以 `AGENTS.md §24.3` 为准。
> 修改本结构 = 同时影响 Web 渲染与 Android 构建期生成，**必须两端一起改**。

## 为什么是 JSON 而不是 JS

Android 端正文硬编码在 smali 的 `const-string` 字面量里（`TutorialActivity.smali:91-149`），
改一次正文就要全量重建 APK。若两端各写一份正文，必然分叉（已经分叉过一次：
Android 侧 10 章、Web 侧 7 章，同一件事两套说法）。

所以本文件是**唯一内容源**：

- Web：`src/core/oreki-tutorial.js` 直接 `import` 本 JSON 渲染；
- Android：构建期由 `scripts/oreki_tutorial_gen.py` 读取本 JSON，生成
  `payload/.../tutorial/TutorialContent.smali`，`TutorialActivity` 只负责循环取值显示。

用 JSON 而不是解析 JS 的原因：Python 解析 JS 对象字面量只能靠正则，Web 侧字段一改就
**静默产出残缺教程**（能编过、能装上、界面空白或少章），只有装机肉眼才发现。
JSON 有 `json.load` 兜底，语法错误在构建期直接报错。

## 顶层

| 字段 | 类型 | 说明 |
|---|---|---|
| `schemaVersion` | int | 结构版本。生成器不认识的版本号必须拒绝构建，不允许降级猜测。 |
| `updatedAt` | string | 最后修改日期 `YYYY-MM-DD`，供两端核对是否同步。 |
| `note` | string | 给维护者看的说明，不渲染。 |
| `chapters` | array | 章节数组，**顺序即阅读顺序**，不得靠 `id` 排序推断。 |

## 章节（十个内容字段 + 元信息）

`AGENTS.md §24.3` 要求每个阶段都有这十个字段，缺一不可：

| 字段 | JSON 键 | 类型 | 要求 |
|---|---|---|---|
| 阶段目标 | `stageGoal` | string | 一句话说清「做到什么程度算过」，必须带数值。 |
| 进入条件 | `entry` | string | 前置判据，带数值或源码出处。无前置写「无前置条件」。 |
| 具体操作 | `steps` | array | 有序操作项，见下。**禁止**「升级到足够高」「继续推进」这类模糊描述。 |
| 购买优先级 | `buyOrder` | array\<string\> | 有序清单，写清「先买什么、什么可以后买、什么不要买」。 |
| 自动化配置 | `automation` | string | 本 MOD 已经代劳的部分要**直说不需要手动**，并写清哪个开关决定它。 |
| 挑战攻略 | `challenges` | string \| null | 本阶段有挑战就写打法与顺序；没有就 `null`，不要写空字符串。 |
| 关键数值 | `numbers` | array | `{label, value, src}`，`src` 必须能定位到源码 `文件:行` 或实测数据文件。 |
| 完成判据 | `done` | string | 可观测的判据（界面上的数字 / 布尔状态），不要写「感觉可以了」。 |
| 下一步路线 | `next` | string | 指向下一章或具体下一步动作。 |
| 常见卡点 | `traps` | array\<string\> | 真实踩过的坑，不是泛泛而谈的「注意资源管理」。 |

元信息：

| 键 | 类型 | 说明 |
|---|---|---|
| `id` | string | 稳定标识，形如 `ch00`。**不得重命名**，Android 侧进度按它记录。 |
| `title` | string | 章节标题，含序号，两端显示一致。 |
| `subtitle` | string | 一句话副标题（数值区间或主题）。 |
| `stageKey` | string \| null | 对应 `STAGE_DEFS` 的 `key`：`early` / `infinity` / `eternity` / `reality` / `celestials` / `doomed`；导览类章节为 `null`。 |
| `draft` | bool | `true` = 尚未写完，生成器允许存在但**发布前必须为 `false`**。 |
| `table` | object \| null | 可选 `{head: [...], rows: [[...]]}`，用于对照表。 |
| `note` | string \| null | 可选补充提示。 |

### `steps` 条目

```json
{ "text": "点底栏「维度」页签。", "auto": false }
```

| 键 | 类型 | 说明 |
|---|---|---|
| `text` | string | 一个可独立执行的动作。一步只做一件事。 |
| `auto` | bool | `true` = 本 MOD 已自动化，玩家**不需要**手动做，此条只用于说明机制。渲染时加「已自动化」标记。 |

## 校验规则（构建期必须全部通过）

1. `schemaVersion` 与生成器支持版本一致；
2. `chapters` 非空，`id` 唯一且连续（`ch00`、`ch01`…）；
3. 每章十个内容字段存在且类型正确；`stageGoal` / `entry` / `done` 非空字符串；
4. `steps` 非空（`draft: true` 的章节除外）；
5. 每个 `numbers[].src` 非空，且形如 `路径:行` 或指向已存在的实测数据文件；
6. 文本里禁止出现占位词：`TODO`、`待补`、`XXX`、`足够高`、`继续推进`；
7. 末端章节（`stageKey == "doomed"`）必须包含终局判据数值 `1e1000` 或 `1000`；
8. **禁用译名黑名单**：正文不得出现 `docs/TUTORIAL_GLOSSARY.md` 第四节列出的任何写法
   （`时间定理`、`稀释时间`、`大灾变`、`星际生成器`、`全部最大`、`艾法瑞格`、`被奴役者`、`雕文`、`刻速`…）。

第 6、7 条是硬门槛：它们正是 `AGENTS.md §24.4`「必须真正可执行」与「必须覆盖真实终局」的机器可检查形式。

### 为什么第 8 条必须是机器检查

译名错误是一种**玩家看不出来**的错误。新手读到「把时间定理买到 6 级」不会觉得有问题——
他会照做，然后发现没有叫「时间定理」的东西，卡在那里。而作者自己也看不出来，
因为他写的时候脑子里就是这个译名。

唯一可靠的判定方式是**统计官方字符串表**：`values-zh-rCN/strings.xml`（4,516 行）里
「时间之理」出现 75 次、「时间定理」**0 次**。0 次就是官方不存在这个说法。
这类事实人工 review 抓不住（本项目已经因为「时间定理」「稀释时间」各错一次），
所以必须写进构建期断言，命中即构建失败。

第 8 条的例外语境：正文**主动纠正**错译时会引用错译，例如
「官方译名是『时间之理』，不是『时间定理』」。这类句子是文档资产，扫描前会按
`(?:不是|禁止写作|不要写成|误译为|错译作|错误写法是)「…」` 剥掉。
不允许用引号把真正的误用包起来蒙混过关——剥除规则只认「明确否定词 + 引号」这一种形态。

### 空字段必须留痕（`E2`）

`challenges: null` 是合法的，它的语义就是「本阶段没有挑战」，这本身就是一种说明。
真正会误导后来者的是**整章字段留着不写、也没有 `note`**——读者无法区分
「这里真的不需要」和「作者漏了」。

所以约定：非草稿章节若存在任何空字段（`buyOrder` / `challenges` / `numbers` / `traps` / `table`），
必须有非空 `note` 说明为什么。这条只管「有没有解释」，不管「解释得对不对」：
它挡不住敷衍，但能挡住静默留空。

## 双端渲染差异（允许范围）

按 `AGENTS.md §24.6`，两端正文、顺序、术语、数值必须一致，**只允许布局差异**：

| 能力 | Web | Android |
|---|---|---|
| 章节目录 | 左侧列表 | 顶部下拉 / 横向页签 |
| 步骤列表 | 有序列表 + 「已自动化」徽标 | 同样内容，单列纯文本 |
| 表格 | 真实 `<table>` | 逐行拆成「标签：值」段落（小屏不横滚） |
| 字号 | 默认 | 提供 小/中/大 三档 |
| 定位 | 按当前阶段自动滚动 | 同逻辑，打开时定位到当前章 |
