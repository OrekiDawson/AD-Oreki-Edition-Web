# 移动端适配测试门禁（Android 模拟器）

**版本** v1.1 · 2026-10-27 · 用户确立
**约束对象**：仅 Web 端（本仓库）在 **Android 模拟器**中进行的移动端适配测试。

> 本文件是 `AGENTS.md §5-A` 的细则。冲突时以 `AGENTS.md` 与本文件为准，
> **不写入 `docs/SHARED_GAMEPLAY_STANDARD.md`** —— 该文件是双端硬链接共享的玩法标准，
> 本条属 Web 端测试流程约定，写进去会给 Android 端塞入与其无关的门禁（见 §1 的第 8 条）。

---

## 1. 门禁条文（原文保留用户口径）

1. 在进行 Android 模拟器上的 Web 移动端适配测试之前，**必须确认模拟器中已安装并实际运行
   最新版稳定版 Chromium 内核浏览器**。
2. 先检查当前环境与已安装版本。**若已满足要求，不重复安装**；若不是最新版，优先使用可信官方渠道更新。
3. **必须记录**：浏览器名称、浏览器版本、Chromium 内核版本、APK 包名或应用标识、安装来源、
   以及核验时间。
4. 更新后**必须在模拟器中实际启动浏览器并核验运行版本**。仅下载了安装包、仅检查宿主机浏览器版本、
   或仅检查模拟器内安装文件，**都不能视为通过**。
5. 门禁通过后，再进行移动端布局、视口、触摸操作、滚动、弹窗、输入、自动机和脚本编辑器等适配测试。
6. 若最新版无法获取、安装失败、模拟器无法运行或实际版本无法核验，**应明确报告阻塞原因**，
   不得将旧浏览器测试结果描述为最新版兼容性验证。
7. 记录测试使用的**模拟器 Android 版本、屏幕尺寸或分辨率、DPI、浏览器版本**，以及关键测试结果，
   便于回归复现。
8. 本条**只约束 Web 在 Android 模拟器中的移动端适配测试**，不要求 Android 原生 APK 的
   普通构建或回归测试也更新浏览器。
9. 先确认现有流程中是否已有等效门禁。**采用最小改动**，保护所有未提交和未跟踪文件。

## 2. 判定口径（把条文变成可执行判据）

| 概念 | 本文采用的判据 | 理由 |
| --- | --- | --- |
| 「最新稳定版」 | chromiumdash 的 `channel=Stable&platform=Android` 返回的**最高两个 milestone 之一** | 滚动发布期同一时间会有相邻两个 milestone 并存（实测 2026-10-27 返回 M156 与 M157），只认一个会误判阻塞 |
| 「Chromium 内核版本」 | 浏览器主版本号（如 `113.0.5672.136` → 内核 113） | Chrome / Chromium / WebView 的主版本号即内核 milestone |
| 「已安装」 | `pm list packages` 中存在该包名，且 `dumpsys package` 能读到 `versionName` | 安装文件存在 ≠ 可用 |
| 「实际运行」 | 有前台 Activity（`topResumedActivity`）+ 有存活进程（`pidof`）；WebView 系额外要求 `dumpsys webviewupdate` 的**运行时提供者版本**与安装版本一致 | 规则 4 明确排除「只看安装包 / 只看宿主机」 |
| 「等效门禁」 | 现存流程中是否有*在模拟器内、用真实设备浏览器*跑适配测试的步骤 | 见 §6 差异核对 |

**版本落后一个 milestone 也算未通过**（规则 1 要求的是最新版）。但**不得**因此把旧内核的测试结果
写成「最新版兼容性」——只能写成「浏览器 X（内核 N）下的实测结果」，并标明门禁未过（规则 6）。

## 3. 核验命令（本机实测可用）

```bash
# 固定前缀：本机 SDK 不在 PATH 里
export PATH="/c/Users/Oreki/Android/Sdk/platform-tools:$PATH"

adb devices -l                                        # 设备是否在跑（期望 emulator-5554 device）

adb shell getprop ro.build.version.release            # Android 版本，实测 14
adb shell getprop ro.build.version.sdk                # API，实测 34
adb shell getprop ro.product.cpu.abi                  # 实测 x86_64（决定 APK 架构）
adb shell wm size                                     # 实测 1080x2340
adb shell wm density                                  # 实测 440

adb shell pm list packages -f | grep -iE "chrome|browser|webview"   # 装了哪些浏览内核
adb shell pm list packages com.android.chrome         # 空输出 = 未安装 Chrome
adb shell dumpsys package <包名> | grep -E "versionName|versionCode|firstInstallTime|lastUpdateTime|codePath"
adb shell dumpsys webviewupdate | grep "Current WebView package"    # 运行时真正生效的内核版本
adb shell cmd package resolve-activity --brief -a android.intent.action.VIEW -d http://example.com  # 默认 http 处理器

# 规则 4：实际启动并核验运行版本（会切走当前前台应用，按需执行）
adb shell am start -a android.intent.action.VIEW -d "http://127.0.0.1:8288/index.html"
adb shell dumpsys activity activities | grep -E "topResumedActivity"
adb shell pidof <包名>
```

**模拟器访问宿主机上托管的 Web 副本**（外网不通时的唯一可靠通道，实测可用）：

```bash
adb reverse tcp:8288 tcp:8288     # 之后模拟器内访问 http://127.0.0.1:8288 即宿主机 8288
adb reverse --list                # 确认映射存在
adb shell ping -c 1 -W 3 10.0.2.2 # NAT 网关可达；8.8.8.8 实测不可达（无外网）
```

**侧载 APKM 分包（模拟器无 Play 商店时唯一的更新方式）**：

```bash
# 1. 先离线校验（不需要 Java；见 _tools/apk-inspect.py）
python _tools/apk-inspect.py _research/_apkm-chrome-156/base.apk
python _tools/apk-inspect.py _research/_apkm-chrome-156/split_chrome.apk
# 2. 解压 .apkm（它本身就是 zip），确认 variant 的 arches 与模拟器 ABI 一致
# 3. 安装：base + 所有 split 一起装，缺 split 会装不上或运行崩溃
adb install-multiple -r --no-streaming base.apk split_chrome.apk split_on_demand.apk split_config.*.apk
# 4. 设成默认浏览器，避免 intent 落到系统 WebView 壳
adb shell cmd role add-role-holder android.app.role.BROWSER com.android.chrome
```

**内核版本核验（比截图 OCR 可靠）**：Chrome 起来后开 DevTools socket，

```bash
adb forward tcp:9222 localabstract:chrome_devtools_remote
curl -s http://127.0.0.1:9222/json/version   # Browser / User-Agent / V8-Version
```

返回里的 `Browser: Chrome/156.0.8078.47` 是**浏览器版本**，UA 里的 `Chrome/156.0.0.0` 是**Chromium 内核大版本**。
两者要分别记录，不能混为一谈（Edge 也同理：Edge 版本号与内核 milestone 同步，但补丁号不同）。

## 5. 自动化

| 项 | 内容 |

## 6. 与现有流程的差异（2026-10-27 核对结论）

| 现有资产 | 实际做什么 | 是否等效门禁 |
| --- | --- | --- |
| `_tools/verify-ui.mjs`（套件 3「设置界面与响应式」） | 在**宿主机 Edge** 用 `setViewport({390,844,isMobile:true,hasTouch:true})` 模拟手机视口 + 700px 窄窗堆叠检查 | **不等效**：宿主机内核，不是模拟器内真实浏览器；无法覆盖软键盘、真实触摸、移动端 GPU/内存 |
| `_tools/shot-mobile.mjs` | 宿主机 Edge 的 390×844 视口截图 | **不等效**，同上 |
| `AGENTS.md §5` 测试与验收 | 只规定宿主机套件、F 值覆盖、存档保护 | 无移动端/模拟器条款 |
| `docs/阶段二/三` 报告 | 明确写过「手机部分只做了视口模拟，没有真机验证」「未加 viewport meta」 | 说明此前**没有**模拟器实测，是已知空白 |
| `docs/SHARED_GAMEPLAY_STANDARD.md` §8.4 验证分级 | 按改动影响面分级，只提宿主机套件 | 无移动端条款 |
| Android 仓库 `AGENTS.md §2` | AVD `oreki_test` 只用于**原生 APK** 测试（`simtest.py`） | 与本条不冲突（规则 8），但可复用同一 AVD 与 adb 前缀 |

**结论**：此前不存在等效门禁，本轮为**新增**，未与现有条款重复或冲突。

| Android | 14（SDK 34），x86_64 | `getprop` |
| 屏幕 | 1080×2340，440dpi | `wm size` / `wm density` |
| **测试浏览器** | **Chrome for Android `com.android.chrome` 156.0.8078.47**（versionCode 807804708，minSdk 32 / targetSdk 36） | `dumpsys package` |
| Chromium 内核 | **156**（UA `Chrome/156.0.0.0 Mobile`；DevTools `Browser: Chrome/156.0.8078.47`、V8 15.6.75.19） | CDP `/json/version` |
| 安装方式 | 侧载 APKMirror 的 **x86_64 variant**（`.apkm` 分包），`adb install-multiple` 28 个 APK；安装时由 Android 平台完成 v2 签名与内容摘要校验 | `adb install-multiple` 返回 `Success` |
| 签名证书 | SHA-256 `f0fd6c5b410f25cb25c3b53346c8972fae30f8ee7411df910480ad6b2d60db83`<br>SHA-1 `38918a453d07199354f8b19af05ec6562ced5788`<br>主题 `C=US, ST=California, L=Mountain View, O=Google Inc., OU=Android, CN=Android` | `_tools/apk-inspect.py`（openssl 验签 `Verified OK`） |
| 默认 http 处理器 | `com.android.chrome/com.google.android.apps.chrome.IntentDispatcher` | `cmd package resolve-activity`（已用 `cmd role add-role-holder android.app.role.BROWSER` 指定） |
| 残留旧内核 | `org.chromium.webview_shell` 1.0（系统壳）+ `com.android.webview` **113**.0.5672.136（未更新） | `dumpsys webviewupdate` |
| 最新稳定版（Android） | chromiumdash Stable 返回 M157 `157.0.8103.14` 与 M156 `156.0.8078.48` / `156.0.8078.47` | chromiumdash，2026-10-27 15:33 查询 |
| Play 商店 / GMS | **无**；第三方应用只有 `com.oreki.antimatterdimensions` | `pm list packages` |
| 外网 | **不通**（`8.8.8.8` 丢包、无 DNS）；`10.0.2.2` 通；`adb reverse` 可用 | `ping` / `adb reverse --list` |

**门禁结论：通过**（`node _tools/mobile-gate.mjs --launch` 退出码 0，记录 `_research/mobile-gate-2026-10-27.json`）。
Chrome 156 属 M156，与 chromiumdash 的 M156 稳定版同分支；patch 级比 `156.0.8078.48` 低一个，
但 `.47` 同样出现在 Stable 列表中（x86_64 变体），因此按 §2 的「最高两个 milestone 之一」判据为最新稳定分支。

**页面加载验证**：`adb reverse tcp:8288 tcp:8288` + 宿主 `python -m http.server 8288 --directory AD-Oreki-Edition`
→ Chrome 打开 `http://127.0.0.1:8288/index.html` → 标题 `AD: Oreki Edition — 反物质维度`，
页内 `fetch` 返回 `HTTP 200`，截图见 `_research/chrome156-webpage.png`（游戏界面已渲染）。
截图顶部的 `No internet connection` 是 Chrome 因模拟器无外网显示的信息条，不影响本地页面。

**未解决 / 需注意**：

1. **Edge APK 不适用于本模拟器**：`com.microsoft.emmx_155.0.4283.48.apk`（SHA-256 `9b4c6885…b924`）
   只含 `lib/arm64-v8a`，而本机 ABI 仅 `x86_64` 且无 ARM 转译（无 `libndk_translation`、
   无 `ro.dalvik.vm.isa.arm64`）。实测安装失败：
   `INSTALL_FAILED_NO_MATCHING_ABIS: Failed to extract native libraries, res=-113`，
   失败后无残留包。且 Edge 155 落后最新稳定版（M155 vs M157），也不满足门禁。
   要用 Edge 需另找 x86_64 变体，本机未验证其是否存在。
2. **系统 WebView 仍是 113**：若测试走 WebView（Android 原生 APK 内的 WebView），内核仍为 113。
   门禁只覆盖「模拟器里的浏览器」，不覆盖 WebView 渲染；两者别混为一谈。
3. **无 Play 商店 / 无外网**：浏览器只能侧载更新，每次更新需重新走 §3 的核验；不要用「下载了安装包」
   或「宿主机浏览器版本」充当证据。
4. **模拟器时钟为 UTC**：`dumpsys` 的 `lastUpdateTime` 比本地时间早 8 小时，记录时以本地时间为准并注明。
