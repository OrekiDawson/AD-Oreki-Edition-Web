# 游戏内教程写作风格规范

> 适用于 Web 与 Android 共用的 `src/core/oreki-tutorial-data.json`。本规范只约束**怎么写**，不改变玩法、公式、解锁、自动化、挑战结算、存档和生产门禁。
> 2026-11-24 R127 专项：[Web #147](https://github.com/OrekiDawson/AD-Oreki-Edition-Web/issues/147)。

## 1. 写给正在玩的人

每章优先回答：**现在做什么、哪些由自动化代劳、怎样确认完成**。开头不要堆开发背景、公式或版本说明。

- 使用自然、准确、简洁的简体中文。保持亲切但不过度拟人化，不说空泛的「稳稳地」「一键起飞」。
- 用「打开『维度』页，查看星系数量」代替「判据一」「本章唯一硬前置」「执行闸门」等验收报告口吻。
- 每条 `steps[].text` 尽量对应一件可执行或可观察的事。若 `auto=true`，说明自动发生的动作，**不暗示玩家必须再手动点**。
- 条件写具体数值，但不强迫玩家阅读内部 `stage=`、`degraded=`、调试变量、R 编号。
- 避免「永远不会」「下一帧一定」「唯一必须」等绝对化断言；自动化依赖真实解锁、资源、开关和调度间隔。

## 2. 作者化表达

- 教程不是操作清单的扩写。以每章独特的玩法问题组织叙述：生产链为何增长、重置为何值得、挑战为何限制规则。先建立玩家的理解，再给可执行动作和可见结果。
- 用适量的观察、对比、探索和幽默建立阅读节奏；不把每章写成同一种开头，不虚构剧情、奖励或机制，不提前泄露不必要的终局内容。
- 章内解释要服务当前游戏阶段；数值、条件、危险操作及自动化标记保留。与 Wiki 事实一致，但不复制百科长文。原版与 MOD 差异继续按附录 F 边界管理。
- 由 ChatGPT 主责作者化正文，Android/Web 责任 Agent 负责同源生成、集成与界面实测。逐章记录作者化、事实、完整性、双端同步和实测状态；只改标题或段首不得认定整章完成。

## 3. 信息分层与字段

**保持现有 schema、章节 ID、顺序和所有十个内容字段。** 不因为语言重写删除有效机制和危险操作提示。

| 字段 | 写法 |
| --- | --- |
| `stageGoal` | 一两句话说清阶段目标与可见的关键数字 |
| `entry` | 仅写真实前置，不将可选支线误写为必经条件 |
| `steps` | 按界面操作先后排列，一条只说一项核心动作或观察 |
| `automation` | 简明解释由谁代劳、哪个开关控制、何时需要手动 |
| `buyOrder` / `numbers` / `table` | 保存必要精确的购买次序、数值、公式，避免混入操作步骤 |
| `done` | 玩家界面能核实的状态，不提出无法达成的条件 |
| `next` | 主线优先，支线明确为可选 |
| `traps` | 描述实际容易遇到的现象及对应检查动作 |
| `note` | 补充背景或字段留空理由，不写开发过程 |

公式不是要删，而是移至适当的数值和机制信息位置。价格、阈值和永久锁定风险仍应精确保留。

## 4. 原版与 MOD 分开

原版机制与 MOD 差异不可混淆。MOD 新增速度、调度和特殊行为集中写在**附录 F**，主线仅保留当前操作必需的说明。不可把 MOD 机制冒充原版，或把旧版本行为当成当前行为。

两套自动化应明确区分：原版自动购买器有原版节拍；本作智能自动操作由调度器管理，默认 10 秒，可设置 1～60 秒。对于**受调度器托管**的原版自动购买器配置，玩家修改后下一次调度 tick 恢复策略值；未托管字段不可一概而论。

## 5. 移除工程报告味

玩家正文不讲「R64 修复」「PR #」「stage=-1」「degraded=0」「以前每帧 Bug」「源码里的方法名」。这些内容放入 Issue、PR、FACTS、开发者记录；游戏教程只表达修复后的正确行为与玩家能看见的结果。

不要为避免「AI 味」而删掉事实，不要为了写得生动凭空增加剧情、条件、操作或奖励。正式游戏名词以 [《教程译名表》](教程术语表.md) 为准。

## 6. 章节顺序与可选内容

主线从基础维度、无限、永恒、现实进入莱特拉、佩勒。薇和太阳神等非必经内容明确标「可选探索」，不要求通关前全部完成。隐藏成就是参考资料，不将不可达成就作为必达条件。维持原章节 ID 与存档进度兼容，必要时通过章节提示调整阅读路线。

## 7. 发布前检查

1. 先以当前源码核实事实，区分已证实文本矛盾与尚未验证机制。
2. 只修改唯一 JSON 正文；运行 `scripts/gen_tutorial_module.mjs` 同步 Web 生成物，Android 以原有同源生成流程验证。
3. 最小检查：18 章、7 附录、0 草稿、字段结构、官方术语、生成文件一致及定向机制核对。
4. Node/浏览器/Android 未实际运行时标 `NOT RUN`，静态核验不能冒充设备 PASS。
5. 不绕过预算、CI、Kody、Ruleset 和任何发布安全门禁。
