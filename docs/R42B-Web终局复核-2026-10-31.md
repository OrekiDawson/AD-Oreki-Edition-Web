### 2.4 同批被找到的第二个真缺陷（r42c-web-endgame 发现，记在这里备查）

`oreki-eternity-automation.js` 的 `holdForRealityUpgrade10()` 原本写 `player.eternities > 0`。
`player.eternities` 是 Decimal，`extensions.js:232` 让 `valueOf` 直接抛
`Implicit conversion from Decimal to number` ⇒ 该函数**每帧抛异常、被 catch 吞掉、恒 false**
⇒「为现实升级 10 压住第一次永恒」这条机制从写下来就没生效过 ⇒ RU10 每个现实都拿不到
⇒ 成就 147 不成立 ⇒ 特蕾莎不出现。

`[静态推导]` 语义等价、无隐式转换；`[未验证]` 压住 10 s 对 RU10 命中率的实际影响需真跑对照。
这条正是规则 2 存在的理由。

## 3. 第 4 项：嵌套对数曲线的数学性质

对象：`MachineHandler.baseIMCap`（`src/core/machines.js:77-81`）

```
cap(L) = max(L − 1000, 0)² · max(L − 100000, 1)^0.2 · 100
其中 L = log10(uncappedRM) = 3·(log10EP / 4000 − 1)        （machines.js:33-38）
```

| 性质 | 结论 | 状态 |
|---|---|---|
| 输入 | `L`（RM 的十进制指数，无量纲）；`log10EP` 是**指数**，不是 EP 本身 | `[静态推导]` |
| 输出 | IM 上限（台数，无量纲），再乘 `ImaginaryUpgrade(13)` 与 `OREKI_IM_CAP_MULT=100` | `[静态推导]` |
| 单调性 | `L>1000` 上严格单调增；`L≤1000` 恒 0。数值抽样 900→12000（步长 1）**非减，0 例外** | `[实测-数值]` |
| 连续性 | C⁰ 连续（`L=1000` 处为 0；`L=100001` 处两段都为 1 倍率）；C¹ 不连续（两处折点） | `[实测-数值]` |
| 边界 | `L≤1000`→0；`L=1000.001`→1.0e-4；`L=1e5+1`→9.8e11（第二因子从常数 1 切换为 `x^0.2`，斜率无穷大但值不跳） | `[实测-数值]` |
| 溢出 | 实际可达 `L≈1.8e4` → cap≈3.0e10，double 安全；要溢出需 `L>1e154`，不可达 | `[静态推导]` |
| 小值行为 | 二次项主导：cap ∝ (L−1000)²，`L` 每 +1 约 +0.16%（相对），前期非常"钝" | `[实测-数值]` |
