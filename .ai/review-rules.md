# Oreki Audit 审查规则（Web / AD-Oreki-Edition）

> 由 **Oreki Audit Bot**（独立 GitHub App）从**默认分支**读取；PR 不能修改本次审查所用规则。
> Web 基线保持上游冻结（`IvarK/AntimatterDimensionsSourceCode` @ `5409e320`），只评审本 PR 的改动。

## 输出契约（强制，缺失即视为审查未完成）

审查正文最后一行必须是：

```
<!-- oreki-audit-verdict {"p0":0,"p1":0,"p2":0,"reviewed_sha":"<PR head 的 40 位小写 SHA>"} -->
```

无问题写全 0；不为凑数编造 P2；评论事件固定 `COMMENT`，阻断由独立 Check 决定。

每条问题写清：**文件:行号 → 触发条件 → 为什么是真实缺陷 → 影响范围 → 最小修复方向 → 置信度**。

## P0（立即阻断）

1. **越阶段解锁**：未真实结算就可达永恒/现实/Glyph 等更高层页面或入口（与 Android 同源判据）。
2. **伪造进度/结算**：写死资源、成就、挑战完成数、EP/RM/ realities；改存档掩盖缺陷。
3. **存档损坏 / 兼容破坏**：改变存档字段语义、导入导出格式、离线结算导致旧档不可用。
4. **崩溃/卡死**：未捕获异常导致页面白屏、无限循环、主线程长任务。
5. **安全**：密钥/Token 入库、`eval` 不可信输入、把用户输入拼进 DOM/HTML。

## P1（阻断）

1. **与 Android 玩法不等价**：同一条件下阶段推进、挑战结算、自动购买器、资源扣费产生不同结果
   （必须指出具体条件；平台固有差异不算）。
2. **阶段门禁/自动购买器**：总开关不及时生效、阶段感知错误、手动操作被自动化覆盖、
   间隔超出 1–60 秒支持范围。
3. **GUI 实时性**：资源/按钮长时间陈旧，或需要频繁切页才刷新。
4. **冻结基线违规**：未经授权升级上游、整包替换、改版本号或发布流程。
5. **部署/Pages**：改动生产部署链路而未验证；线上资源与源码 SHA 不一致。
6. **绕过确定性检查**：删除/跳过测试、`continue-on-error`、伪造 PASS。

## P2（不阻断）

性能、可维护性、日志噪音、命名与注释；须给出可执行的最小改动。

## 明确不做

- 不评审生成物（`dist/`、打包产物、sourcemap）；
- 不代替 Playwright / Android Chrome 手机视口实测；代码审查通过 ≠ 线上验收通过。
