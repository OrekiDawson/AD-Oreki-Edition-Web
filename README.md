# 反物质维度 · Oreki Edition（Web）

**在线游玩：<https://oreki.net>**

《Antimatter Dimensions》的网页改造版，以「**爽玩优先**」为目标：保留有意义的手动决策，把重复等待与重复点击交给自动化，尽量缩短从新档到终局的现实时间。

非官方、非商业，与原作者及任何发行方无隶属关系。

> 与 Android 版的关系：同一玩法的两个平台实现，共用玩法语义与教程数据，但代码库、存档互不通用。
> Android 版见 [AD-Oreki-Edition-Android](https://github.com/OrekiDawson/AD-Oreki-Edition-Android)。

## 当前状态

**已实现并验证**：简体中文界面、全局速度系统、自动购买器全链路、智能调度器、挑战自动化、存档导入导出、移动端布局。

**长期目标，尚未达成**：全新存档 180 分钟到达真实终局。这是目标，不是已完成的结论。

## 功能介绍

- **游戏速度**：统一倍率作用于生产与自动器节拍，游戏内计时按倍率压缩，现实时间统计保持真实。
- **简体中文**：完整界面与教程本地化，术语与官方简中一致。
- **自动购买器**：反物质维度、速度升级、维度提升、星系、大坍缩、无限维度、永恒、现实，逐项可控。
- **智能自动化**：统一调度器按阶段与资源状态决定行动，含资源预留、挑战避让、失败冷却。
- **挑战与重置**：普通 / 无限 / 永恒挑战自动进入与结算，含 EC 时间倍率修正。
- **存档工具**：一键导出 / 导入存档，支持跨设备迁移。
- **移动端**：手机浏览器直接可玩，界面针对窄屏适配。

## 快速开始

### 在线游玩

打开 <https://oreki.net> 即可，无需安装、无需注册。
存档保存在浏览器 `localStorage`，**清除浏览器数据会丢失存档**。

### 本地运行

需要一个静态 HTTP 服务（ES Module 不允许 `file://` 加载）：

```bash
node serve.mjs 8080
# 或
python -m http.server 8080 --bind 127.0.0.1
```

然后访问 <http://127.0.0.1:8080>。

### 备份存档

游戏内 **选项 → 导出存档** 复制文本保存；恢复时粘贴到「导入存档」。
换浏览器、清缓存、换设备前都应先导出一次。

### 手机游玩

直接用手机浏览器打开在线地址即可，推荐横屏或全屏模式。
iOS Safari 与 Android Chrome 均已适配；其他浏览器未逐一验证。

## 使用指南

### 速度设置

**选项 → 游戏玩法 → 速度倍率**。倍率只影响游戏内推进速度，不影响现实时间记录与离线结算口径。

### 自动购买器

**自动购买器页**逐项开关；**选项 → 自动化**里可设置总开关与执行间隔（1~60 秒）。
关闭总开关后所有自动行为立即停止，不会残留排队的动作。

### 智能自动化

开启后由统一调度器接管，按当前阶段挑选最该做的事，而不是固定轮询。
它不会绕过节拍间隔，也不会在你手动操作时抢占。

### 挑战与重置

挑战可自动进入并结算；重置类操作（大坍缩 / 永恒 / 现实）在满足条件时自动执行。

### 注意事项

- 长时间挂机建议先导出存档。
- 浏览器后台标签页会被降频，实际推进速度可能低于前台。
- 修改速度倍率后建议刷新页面再观察，避免读到旧的节拍缓存。

## 开发者快速开始

### 环境要求

- Node.js 任意 LTS（仅用于本地静态服务与测试脚本）
- 现代浏览器（Chrome / Edge / Safari）
- 无构建步骤：源码即产物，直接由浏览器加载 ES Module

### 本地开发

```bash
node serve.mjs 8080     # 起服务，改完刷新浏览器
node scripts/test-r83-iu15-sprint.mjs   # 示例：定向测试
```

### 代码结构

```
src/
├── game.js                 主循环与调度器接线
├── core/
│   ├── dimensions/         维度与无限维度
│   ├── autobuyers/         各自动购买器
│   ├── celestials/         天体（含莱特拉）
│   ├── secret-formula/     数值与升级定义（含 IU15 门槛）
│   └── oreki-*.js          MOD 自动化模块
└── components/             界面组件
scripts/                    定向测试与生成脚本
```

### 教程唯一数据源

`src/core/oreki-tutorial-data.json` 是教程的唯一内容源，`oreki-tutorial-data.gen.js` 由生成器产出。
Android 版的内置教程也由同一份 JSON 生成 —— **改教程只改这个 JSON**，不要手改生成物。

### 开发要求

- 新增代码配必要的简体中文注释。
- 购买一律走原版入口，不直接写存档字段。
- 自动化必须遵守统一节拍，不新增独立计时器。

## 测试与验收

### 定向测试

改哪里验哪里，不做无差别全量回归：

```bash
node scripts/test-r83-iu15-sprint.mjs    # IU15 冲刺状态机
node scripts/test-scheduler-beat.mjs     # 调度节拍
node scripts/test-early-ipmult.mjs       # 前期 IP 倍率
node scripts/validate_tutorial.mjs       # 教程数据完整性
```

### Android Chrome 默认视口

移动端改动必须在真实 Android Chrome 默认视口验证一次，不用桌面仿真代替。

### 响应式修改

涉及布局的改动需额外检查窄屏（360px）与横屏，确认无横向溢出与遮挡。

### 里程碑测试

版本升级、存档结构变更、共享调度器改动时扩大范围。

### 当前限制

- 180 分钟通关未在真实新档验证。
- iOS Safari 只做过基础功能验证，未做逐页回归。
- 后台标签页降频导致的推进偏差未量化。

## 部署与发布

线上站点由**独立的部署仓库**提供，源码仓库不直接对外服务：

| 仓库 | 职责 |
|---|---|
| `AD-Oreki-Edition-Web`（本仓库） | 源码、测试、教程数据源 |
| `OrekiDawson.github.io` | 部署副本，只放构建产物 |

同步流程：把 `src/` 下变更的文件按原换行风格复制到部署仓库对应路径 → 提交 → 推送 `main` → GitHub Pages 自动发布 → 回读线上文件核对与本地一致。

部署仓库的详细维护说明见其自身 README。
