## 二、事实核对：三处「核之前以为是，核之后实际是」

### 2.1 Esc 不派发 `CLOSE_MODAL`

- **核之前**：上一版用 `this.on$(GAME_EVENT.CLOSE_MODAL, ...)` 判定「这次销毁是不是玩家关的」，
  注释里还写着「× / 关闭教程 / **Esc** 都会派发 CLOSE_MODAL」。
- **核之后**：`hotkeys.js:476-480` 的 `keyboardPressEscape()` 只有一句 `else if (Modal.isOpen) Modal.hideAll();`，
  而 `Modal.hideAll()`（`modal.js:167-177`）是「逐个出队 + `current = undefined`」，**整个 `modal.js` 里没有
  任何 `CLOSE_MODAL` 的派发**（`grep -n CLOSE_MODAL src/core/modal.js` 零命中）。
- **后果**：上一版会把「按 Esc 关掉」误判成「被高优先级弹窗顶掉」，下次打开**跳回上次那一章**，
  等于在 Esc 路径上把「主动关闭不粘位置」这条验收打破了。
- **现判据**：`beforeDestroy` 时查 `ui.view.modal.queue` 里还有没有本组件 —— 在 = 被顶掉（`current` 换人、
  队列没动）；不在 = 玩家关的（× 走 `Modal.hide`、Esc 走 `Modal.hideAll`，都会出队）。

### 2.2 `beforeDestroy` 里读 `$refs.scroll.scrollTop` 拿到的是 0

- **核之前**：以为 ref 在 `beforeDestroy` 时还指着 DOM，可以直接读。
- **核之后**：实测在「被顶掉」这条路径上读到 `0`（脚本输出 `{"chapterId":"ch10","scrollTop":0}`），
  而 DOM 上明明是 420。Vue 在销毁阶段已经把这个 ref 摘掉了。
- **改法**：`onScroll` 在滚动过程中就把 `scrollTop` 写进 `TutorialReadingPosition`，
  `beforeDestroy` 只负责「用户主动关闭时清零」。

### 2.3 上一版报告里「熵分母 7500 → 2e7」是错的

- **核之前**：`R40E-ch15自查与编号脚本契约.md` 写「只有一处是本作改的：熵的分母 `7500 → 2e7`」。
- **核之后**：`diff` 直读原版 `upstream/official/src/core/celestials/laitela/laitela.js:57` 是
  `... / 1e11, 2) ... / 200`；本作 `laitela.js:81-83` 换成 `OREKI_LAITELA_ENTROPY_DIVISOR = 2e7`（`:30`）。
  **7500 是鹿颈长碎片产量的除数**（原版 `core/celestials/effarig.js:75`；本作
  `OREKI_EFFARIG_SHARD_DIVISOR = 30`，`effarig.js:191-193`），与熵无关。
- **影响面**：教程正文本来就写 2e7（`ch15.numbers[2]` 的 value 是 `clamp((log10(反物质)/2e7)², 0, 100)/200`），
  没有受影响；错的只是报告里的一句概括。已在原报告该行下方加「更正」块，原文保留。

### 测试过程中修掉的三个测试缺陷（都是「我测错了」，不是产品错）

1. **同帧赋值 + 弹窗**：脚本「设 `scrollTop=420` → 立刻弹消息」，scroll 事件要等下一帧才派发，
   组件那时已销毁 → 测出 0。真实玩法是「滚完读一会儿才被打断」。改成赋值后等 400 ms，差值 0px。
2. **未 drain 就开测**：新档 10 秒内真的会解锁成就 55（priority 3 的说明），这条消息留在队列里时
   教程只是「排在队列里」、根本不会挂载，于是后面测出的 `scrollTop=-1` 是「元素不存在」。
   现在每次断言教程本体前先 `drain()`。
3. **消息文本撞车**：合成消息写的是「测试：由于你在 1 分钟内完成了一次无限…」，
   而真成就 55 的文案里也有「1 分钟内完成了一次无限」，用 `includes` 判定会把新消息当残留。
   改成用 `startsWith("测试：")`。
