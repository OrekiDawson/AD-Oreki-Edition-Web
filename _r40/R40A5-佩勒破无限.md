## 0. 一句话结论

上一轮（R40-A4）判定的「死锁不是墙」是对的，但**只补末日循环还不够**：
买到 `keepAutobuyers` 之后还卡在「拉满 15 级间隔」这一段，
因为毁灭态里 **大坍缩自动器根本没解锁**（`PelleStrikes.infinity.hasStrike` 为 false），
置 `isActive = true` 是纯空转 —— 实测 557 s 零 IP。

本轮把它拆成两件事：

1. **末日循环**（先买、后末日）→ 拿遗迹碎片买 `keepAutobuyers`；
2. **IP 脉冲**（买不起下一级间隔时，自己按一次 UI 大坍缩按钮）→ 拿 6.2e9 真实 IP，
   顺带解锁「无限冲击」，让间隔能一次拉满 15 级。

两件都成立后，**原版通路 `reality.js:749-752` 自己就把 `player.break` 置 true**，
我们一行都没写 `player.break = true`。

## 1. 本轮改了什么

只动了两个文件（`src/game.js:212`、`game-end.js`、`OREKI_PELLE_END_*`、EC 链一个字没碰）。

### 1.1 `src/core/oreki-break-infinity-gate.js` — `Pelle.isDoomed` 拆成 A/B 两半

| 段 | 内容 | 毁灭态 |
| --- | --- | --- |
| A | `bc.upgradeInterval(false)` 逐级买间隔（真实扣 IP，全仓只有 UI 按钮走这条路） | **放行** |
| B | 一次性把 IP 补到 `BREAK_INTERVAL_TOTAL_COST = 32767` | **拦住** |

- `active()` 里删掉了原来的 `if (Pelle.isDoomed) return false;`（那是 R37 时代的写法，
  它把毁灭态唯一能拉满间隔的自动化掐死了），改为落到 `hasMaxedInterval` 判断上。
- `tryOpen()` 里 B 段加 `!Pelle.isDoomed`。
  理由（team-lead 的措辞，已写进注释）：**原版靠现实重置置 break，不靠发钱**。
  在毁灭态补 32767 IP 等于我们替玩家付账，「真实通关」口径就破了。

### 1.2 `src/core/oreki-endgame-automation.js` — 末日循环 + IP 脉冲

| 位置 | 改动 |
| --- | --- |
| 文件头 R38-M 段之后 | 新增「R40-A5 反证 + R40 晚间定案」注释：`oreki-endgame-automation.js:130-151`，逐行说明「大灾变也要停」那条结论下反了，以及 `reality.js:749-752` 才是原版开 Break 的通路 |
| `driveDoomed()` | 重排为 ⓪重置购买器 → ①maxAll → ②升维/星系 → ③佩勒升级（`keepAutobuyers` 优先）→ ④`_pulseDoomedCrunch()` → ⑤`_maybeArmageddon()`。**先买、后末日** |
| `_maybeArmageddon()`（新增） | 相位机：`broken` / `wait-remnants` / `cooldown` / `max-interval` / `grow` / `armageddon` |
| `_pulseDoomedCrunch()`（新增） | 见 1.3 |
| `_stopDoomedResets()` | 回到无参版本（`allowCrunch` 删掉），自动器**全程关闭** |
| `debugState` | 加 `doomPhase / doomArmageddons / doomBreakAt / doomCrunchesOn / doomKeepAutobuyers / doomShardsL / doomRemnants / doomRemnantsGain / doomBcInterval / doomBcCost / doomIpL / doomStrikeInfinity` |

末日判据（不是「能末日就末日」）：

- 没买到 `keepAutobuyers`：`Pelle.canArmageddon`（`remnantsGain ≥ 1`）
  **且** 反物质指数停滞 `DOOM_STALL_MS = 6000` **且** 距上次 ≥ `DOOM_ARMAGEDDON_MIN_MS = 20000`。
  含义：本轮产量已经顶到 1.8e308 天花板，再等只是空转。
- 已买到 `keepAutobuyers`：只要求间隔已满 + 最小间隔闸门。
  含义：原版的开 Break 判定只在 `finishProcessReality` 里执行，「买齐 → 立刻末日」就是玩家会做的动作序列。
- `player.break === true` 之后一律不再末日（任何重置都只是在推迟 endState）。

### 1.3 本轮新增的关键一手：`_pulseDoomedCrunch()`

```
if (player.break) return;                 // 已经破了，不需要
if (!keepAuto.isBought) return;           // 不需要 IP，坍缩只会拖慢残迹
if (bc.hasMaxedInterval) return;          // 已满
if (IP >= bc.cost) return;                // 买得起，交给闸门 A 段去买
if (!Player.canCrunch) return;            // 反物质没到 1.797e308，按了也是空操作
bigCrunchResetRequest(true);              // = BigCrunchButton.js:18 的同一路径（禁动画版）
```

为什么不能靠自动器（**这是对上一轮方案的实测更正**，见 §5）：
`big-crunch-autobuyer.js:14-18` 在毁灭态 `return PelleStrikes.infinity.hasStrike`，
而「无限冲击」要一次真坍缩才会解锁（`big-crunch.js:58`）。
所以按一次大坍缩按钮**本身就是解锁自动器的那一步**，收益 `gainedInfinityPoints()` 实测 6.2e9，
≫ 32767，一次就够；副作用只有幂等的 `PelleStrikes.infinity.unlock()`（`strikes.js:33-45`，只解锁不重置）。

## 5. 为什么「只放行大坍缩自动器」不够（对上一轮方案的实测反证）

上一轮我按 team-lead 批准的方向，在 `keepAutobuyers` 已买、间隔未满时
把 `Autobuyer.bigCrunch.isActive` 放行。`r40a5-arm1`（1800 s）结果：

```
t≈1411: doom=1 end=0.750601 am=1.7976931348623157e+308 totAML=316.342
        brk=0 keepAuto=1 ivl=150000 ipL=null  phase=max-interval  cr=3137→3215
        arm=1  已卡 557 s
```

现场只读（`live-peek3.mjs` 连 CDP）：

```json
{ "bcUnlocked": false, "bcActive": false, "bcCanTick": false,
  "strikeInfinity": false, "ip": "0", "gainIP": "6233438351",
  "canCrunch": true, "ivl": 150000, "bcCost": 1, "keepAuto": true }
```

根因一行：`big-crunch-autobuyer.js:14-18`
`if (Pelle.isDoomed) return PelleStrikes.infinity.hasStrike;`
—— 没吃过「无限冲击」的毁灭态里它**根本没解锁**，`isActive=true` 不产生任何 tick，
`CanTick` 也不算，IP 永远 0，`hasMaxedInterval` 永远拉不满。

本轮修法（§1.3）就是补上「按一次按钮 → 拿 IP + 解锁冲击」这一步，
并且**保留**了上一轮那半条正确结论：自动器始终关着（它会按 `AMOUNT` 模式把反物质反复清零，
正好破坏 R38-M 要的单调增长）。
