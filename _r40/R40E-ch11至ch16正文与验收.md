## 三、逐章独立验收（每章至少两处回源码）

标注口径：`[读码]` = 直接读源码确认；`[推断]` = 由源码公式推出但未实测；`[实测]` = 运行时观测。

### ch11 现实与符文

**① 符文能不能装备，靠的不是符文等级**
- 核之前我以为：符文等级太高会「装不上」，界面会提示「等级过高」。
- 核之后实际 `[读码]`：全仓 grep 「等级过高 / 等级超出 / 无法装备」只有一处命中，是 `PelleEffectsModal.js:36` 的佩勒文案。符文没有等级门槛，限制只有**槽位数量**：`Glyphs.activeSlotCount = 3 + RealityUpgrade(9) + RealityUpgrade(24)`（`src/core/glyphs/glyph-core.js:66-72`）。
- 后果：旧稿第 5 步整段「等级越高越难装」是**编的**，已删。改成「默认 3 个槽，RU9 与 RU24 各 +1」。

**② RU9 / RU24 是永久锁，不是暂时不可用**
- 核之前我以为：RU9（+1 符文槽）随时能买，只是钱不够。
- 核之后实际 `[读码]`：两条都是 `canLock: true`。
  - RU9：`hasFailed = 装了 >1 个符文 || (装了 1 个且等级 <3)`（`reality-upgrades.js:123-140`）。只要在买下 RU9 之前装第二个符文，这个槽**永久没了**。
  - RU24：`hasFailed = 装备的非同伴符文数 > 0`，且 `checkEvent = REALITY_RESET_BEFORE`（`reality-upgrades.js:373-385`）。某次现实结算时带着符文就永久锁死。
- 后果：这两条直接决定成就 147（`购买所有现实升级`）能不能拿到，而 147 是特蕾莎唯一的入场券 —— 也就是整条天神链的起点。已写进 ch11 的第 1、2 条坑，并在 ch13 第 1 步回指。

**③ 自动化怎么处理这五条形态升级**（不是错误，是补全）
- 核之后实际 `[读码]`：`oreki-reality-automation.js` 的 `satisfyGlyphRequirements()` 按 `9 → 24 → 16 → 17 → 18` 的顺序装卸符文（`:424-440`），五条全拿到才切回「装评分最高的 3 个」。
- 模块注释写的是 `9 → 16 → 17 → 18 → 24`，与代码顺序不一致；以代码为准，教程按代码写。

### ch12 复兴树、自动机与黑洞

**① 自动机到底几点解锁**
- 核之前我以为：25 点（凭记忆里的原版印象）。
- 核之后实际 `[读码]`：`Player.automatorUnlocked = AutomatorPoints.totalPoints >= 100`（`src/core/player.js:1001-1003`），`pointsForAutomator = 100`（`src/core/automator/automator-points.js:31-33`）。
- 顺带核出来源：现实次数每次 +2、封顶 50 次 = 100 点（`secret-formula/reality/automator.js:540-546`），也就是**第 50 次现实自动解锁**。这个数写进了 steps[8] 和 table。

**② 复兴节点是不是越深越贵**
- 核之前我以为：按树深度递增（原版印象里像是有阶梯价）。
- 核之后实际 `[读码]`：`get cost() { return 1; }`（`src/core/perks.js:32-34`），**所有节点一律 1 点**；限制只有连通性 `id === 0 || connectedPerks.some(p => p.isBought)`（`:36-38`）。
- 后果：买点策略从「攒够再买深的」改成「有点就买，先把起点线铺开」。

**③ ACHNR 是不是「第二条就能买」**
- 核之前我以为：ACHNR 是一个 1 点的孤立节点，攒到第一个点数就能顺手买下。
- 核之后实际 `[读码]`：复兴树的连接表里 `firstPerk → achievementGroup1 → achievementGroup2 → achievementGroup3 → achievementGroup4 → achievementGroup5(ACHNR)` 是一条链（`secret-formula/reality/perks.js:509, :542-545`），前面压着 ACH1~ACH4 四个节点，**拿到 ACHNR 实际要 6 点**。
- 后果：旧稿的 buyOrder 写「ACHNR（1 点）」，已改成「ACH1 → ACH2 → ACH3 → ACH4（各 1 点）→ ACHNR（共 6 点）」，并在坑里点明「ACHNR 前面压着四个节点」。顺带把 ACH1~ACH4 的自动发成就间隔（20 / 12 / 6 / 2 分钟）补进正文，让这 6 点不是纯为最后一项花。

**④ 黑洞初始占空比**
- `[读码]` 间隔 `3600 × 0.8^n`、持续 `10 × 1.3^n`（`black-hole.js:68-103`），初始 10/3610 = **0.28%**。这个数写进了 steps[5] 与第一条坑，用来解释「为什么刚解锁的黑洞像没生效」。

### ch13 特蕾莎、鹿颈长、无名氏

**① 无名氏怎么解锁**
- 核之前我以为：要集齐 8 条提示（因为 `secret-formula/celestials/enslaved.js` 里有一张 8 条的 `progress` 表）。
- 核之后实际 `[读码]`：`Enslaved.isUnlocked` 返回的是 `EffarigUnlock.eternity.isUnlocked`（`src/core/celestials/enslaved.js:178-180`）。那张 8 条表是**提示语**，不是解锁条件。鹿颈长的「永恒」阶段一解锁，无名氏就出现。
- 后果：旧思路「收集提示」整段删掉，改成「在鹿颈长现实里做一次永恒」。

**② 鹿颈长解锁位的价格**
- 核之前我以为：1e7 / 2e8 / 3e9 / 5e11 遗迹碎片（`secret-formula/celestials/effarig.js:2-40` 里的 `cost`）。
- 核之后实际 `[读码]`：`EffarigUnlockState.cost` 返回 `new Decimal(base).dividedBy(OREKI_EFFARIG_UNLOCK_COST_DIVISOR)`，常量为 `1e6`（`src/core/celestials/effarig.js:67, :255-259`）。运行时实际是 **10 / 200 / 3000 / 5e5**。
- 后果：如果不写这个缩放，读者会以为要攒 5e11 碎片（按实测产率要几万次现实）。已按 5e5 写，并在 numbers 里同时给出原版值。

**③ 遗迹碎片公式的除数**
- `[读码]` `floor((EP 指数 / 30) ^ 已装备符文词条数) × 炼金鹿颈长倍率`（`src/core/celestials/effarig.js:191-194`）。原版除数是 7500，本作 `OREKI_EFFARIG_SHARD_DIVISOR = 30`（`:44`）。
- 教程据此写「堆 EP 指数比堆词条数更划算：指数涨 10 倍，碎片涨 10^词条数 倍」——这是公式的直接推论 `[推断]`。

### ch14 薇、太阳神

**① 薇的解锁是不是「完成无名氏」**
- 核之前我以为：天神链是线性的，做完无名氏就轮到薇。
- 核之后实际 `[读码]`：`V.canUnlockCelestial` → `VUnlocks.vAchievementUnlock.canBeUnlocked`（`src/core/celestials/V.js:174-176`），前置是 **6 项 mainUnlock 在同一现实内全部 `progress() >= 1`**：现实次数 60 / 永恒次数 1e70 / 无限次数 1e160 / 本纪最高膨胀时间 1e30 / 本纪最高复制器 1e20000 / 当前 RM 1e60（`secret-formula/celestials/v.js:69-120`，其中 60 是 `OREKI_V_UNLOCK_REALITIES`，原版 10000）。
- 后果：解锁动作的描述从「做完上一个天神」改成「等第 60 次现实」——因为其余五项实测在现实次数 15 左右就达标（`secret-formula/celestials/v.js:65` 注释里的 R37-A 记录）。

**② 太阳神要多少空间定理**
- 核之前我以为：100（原版印象）。
- 核之后实际 `[读码]`：`Ra.isUnlocked = V.spaceTheorems >= 36`（`src/core/celestials/ra/ra.js:366-368`）。而 `spaceTheorems = 前六项档数之和 + 后三项档数 × 2`（`src/core/celestials/V.js:189-196`），前六项各 6 档 → 正好 36。
- 后果：教程把「36」和「前六项打满」写成同一个判据，并给出「后三项每档算 2 点」的换算，避免读者以为要打满九项。

**③ 这条线到底要不要做**
- `[读码]` `oreki-celestial-automation.js:245-253` 的注释写明 R37-A 起**不再自动进入 V 的现实**，理由是终局链 `IU15 → 莱特拉 → IU25 → 佩勒` 不依赖薇或太阳神。
- 教程据此在 ch14 最后一条坑与 ch16 最后一条坑都写了「跳过第 14 章也能通关」。这不是偷懒，是模块作者已经验证过的路径选择。

### ch15 莱特拉

**① 暗物质维度有几层**
- 核之前我以为：8 层（因为 `Laitela.maxAllowedDimension = 8 - difficultyTier` 里有个 8）。
- 核之后实际 `[读码]`：`DarkMatterDimensionState.dimensionCount = 4`（`src/core/celestials/laitela/dark-matter-dimension.js:223`），解锁位是 `ImaginaryUpgrade(tier + 14)`，即 IU15~IU18（`:26-33`）。`8 - tier` 说的是**被禁用的普通反物质维度层数**，两者不是一回事。
- 后果：table 与 numbers 都改成「4 层」，并专门留了一条坑解释这个混淆。

**② IU15 到底要多少反物质**
- 核之前我以为：1.5e12（`oreki-endgame-automation.js:17` 的注释是这么写的）。
- 核之后实际 `[读码]`：`checkRequirement = player.requirementChecks.reality.maxID1.eq(0) && player.antimatter.exponent >= OREKI_IU15_AM_EXP`（`secret-formula/reality/imaginary-upgrades.js:215-216`），`OREKI_IU15_AM_EXP = 1e8`（`:49`）。要求的是**指数** ≥ 1e8，即反物质本身 ≥ 1e100000000。
- 结论：`oreki-endgame-automation.js` 头注释那句 1.5e12 是 R37-A 的旧值，R38 改过常量但注释没同步。教程按常量写，并在 numbers 里点明「是问指数，不是问数值」。这条需要 team-lead 决定要不要让该模块的注释跟上（不在我的写入范围）。

**③ 飞升的判据**
- `[读码]` `ascend()` 第一行 `if (this.interval > this.intervalPurchaseCap) return;`（`dark-matter-dimension.js:215-221`），即**间隔买到 10 级上限才能飞升**；每次 `+500` 暗物质强度与 `+500` 暗能量强度（`:13-16`）。

### ch16 佩勒与终局

**① 终局判据到底是什么数**
- 核之前我以为：反物质 9e15（原版 `TARGET = 9e15`）。
- 核之后实际 `[读码]`：`OREKI_PELLE_END_TARGET_EXP = 1e3`、`OREKI_PELLE_END_OFFSET = 1`（`src/core/celestials/pelle/game-end.js:69-70`），
  `endState = (log10(log10(totalAM)+1) − 1) / (log10(1001) − 1)`（`:75-80`）。
  令 `E = log10(totalAM)`，`endState ≥ 1 ⟺ log10(E+1) ≥ log10(1001) ⟺ E ≥ 1000`。
- 结论：判据就是**反物质指数 ≥ 1000**，即反物质 ≥ 1e1000，与 `game-end.js:44-58` 的推导一致。这条写进了 stageGoal、steps[5]、done 与第 7 条规则要求的 `1e1000` 字面量。

**② 遗烬收益是不是线性**
- 核之前我以为：按日志差值线性累加。
- 核之后实际 `[读码]`：`((log10(总反物质+2) + log10(总无限点数+2) + log10(总永恒点数+2)) / 1.64)^7.5`，再减已持有遗烬（`src/core/celestials/pelle/pelle.js:271-287`）。是**三个量的对数之和的 7.5 次方**。
- 后果：教程里写「三项都要堆，缺一项拉低一个数量级」，并给出完整公式。

**③ IU25 的永久锁**
- `[读码]` `canLock: true`、`lockEvent: "装备另一个类型不是同伴的符文"`、`hasFailed` 包含 `Glyphs.activeWithoutCompanion.length > 1`（`imaginary-upgrades.js:359-366`）。进莱特拉之前必须把符文卸到 1 个以内，否则 IU25 锁死、佩勒进不去。已写进 ch16 的第一条坑。

1. **本轮没有重跑浏览器 DOM 验收。**
   原因：上一轮已定位「教程弹窗打开约 2.4 秒后自行消失、`Modal.current` 全程 null、对 `Modal.show/hide` 打桩一次都没记到」，判断在 Modal 注册侧而非 JSON，已上报 team-lead 且至今未见修复结论。在这个前提下跑 DOM 断言只会得到「2.4 秒后元素消失」的同一个结论，无法验证 ch11~ch16 的渲染是否正确。等 Modal 侧修好后建议补一次「逐章打开 + 九块标签 + table 行数」的自动断言。

4. **ch12 的「复兴树优先买哪些节点」是基于节点效果描述排序的**（`secret-formula/reality/perks.js`），没有做「买了 A 之后 60 秒产量对比 B」的实测对照，属 `[推断]`。
