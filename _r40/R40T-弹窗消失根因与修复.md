# R40T 教程弹窗「2.4 秒消失」根因与修复

> 结论先行：**弹窗从来没有被关闭，它是被一条更高优先级的成就说明盖住了**；
> 真正会伤到玩家的是「被盖住 → 组件被销毁 → 回来时阅读位置归零」。
> 修好之后实测 7/7 通过。本文所有结论都有栈或 DOM 观测支撑，没有推断。

---

## 一、先纠正上一轮的两个测量错误

| 上一轮的说法 | 实际 | 依据 |
|---|---|---|
| 「`Modal.current` 全程 null」 | `Modal` 类上没有 `current` 这个静态字段，真正的状态是 `ui.view.modal.current`。读 `Modal.current` 恒为 `undefined`，所以那句话不是证据 | `modal.js:128/143-157/159-177` |
| 「弹窗 2.4 秒后消失」 | 2.4 s 不是关闭时间，是「第一次大坍缩 → 成就 55 解锁 → 弹出 priority 3 的说明」的时间差 | 见 §二 的栈 |

另外，上一轮的探针脚本本身有缺陷：我一开始用 `Object.defineProperty` 重定义 `ui.view.modal.queue/current`，
这会**掐断 Vue 的响应式**（把访问器换成普通属性），结果 `current` 明明有值、DOM 永远不更新，
于是测出「dom=false 全程都在」的假象。v2 脚本改成只包 `removeFromQueue` / `Modal.hide` / `Modal.hideAll`，
不碰响应式，才拿到真实数据。

## 二、根因（有栈）

复现脚本：`web/_tools/_r40/r40t-modal-trace2.mjs` + `r40t-msg-who.mjs`。

时间线（全新存档，`OrekiTutorialModal.show()` 后每 100 ms 采样）：

```
t=500ms  q=1 cur=OrekiTutorialModal dom=true
...
t=3000ms q=1 cur=OrekiTutorialModal dom=true
t=3100ms q=2 cur=MessageModal      dom=false   ← 被顶掉
```

覆盖者的完整栈（`r40t-msg-who.mjs` 抓到的原文）：

```
@7427ms prio=3 text=由于你在 1 分钟内完成了一次无限，屏幕上的 UI 发生了变化。……
  at AchievementState.unlock (src/core/achievements/normal-achievement.js:64:21)
  at AchievementState.tryUnlock (normal-achievement.js:50:10)
  at Object.fn (normal-achievement.js:12:57)
  at EventHub.dispatch (src/core/event-hub.js:26:15)
  at bigCrunchReset (src/core/big-crunch.js:56:14)
```

**机制**：

1. 教程注册为 `new Modal(OrekiTutorialModal)`，`priority = 0`（`modal.js:239`）。
2. 成就 55 解锁时走 `Modal.message.show(text, {}, 3)`（`normal-achievement.js:64`），
   而 `Modal.message` 是 `new Modal(MessageModal, 2)`（`modal.js:350`），
   且 `show()` 里的 `messagePriority` 会把这次调用抬到 **3**。
3. `Modal.show()` → `sortModalQueue()` 按 priority 降序排 → `current` 变成 MessageModal（`modal.js:150-157`）。
4. `PopupModal` 只渲染 `view.modal.current`（`GameUiComponentFixed.js:84-87` → `PopupModal.js:65`），
   于是 `<component :is>` 从教程换成消息 —— **教程组件被销毁**，但**仍在队列里**（`q=2`）。
5. 玩家点掉消息后 `Modal.hide()` 把队列首位移除，`current` 回到教程，组件**重建**（`r40t-msg-restore.mjs` 实测：
   `after click: q=["OrekiTutorialModal"] cur=OrekiTutorialModal dom=true`）。

所以「关掉」是假的，「位置丢失」是真的：组件重建会重跑 `data()`，而 `data()` 里
`index: getTutorialStartIndex()` 会把章节**重置到当前阶段那一章**。

## 三、复现证据：位置确实会丢

修之前的行为可以用修复后脚本的最后一项反证 —— 同一份存档上 `getTutorialStartIndex()` 返回的是
**第 7 章**。也就是说玩家跳到第 10 章 → 被成就说明顶掉 → 点掉消息 → 回来落在**第 7 章**。

## 四、修了三处

### 1. `ModalWrapperChoice` 增加 `useEnterToConfirm`（默认 true）

`ModalWrapperChoice.created()` 无条件把全局「确认弹窗」热键（Enter）接到 `doConfirm()`，
没传 `confirmFn` 时直接 `dispatch(CLOSE_MODAL)`（`ModalWrapperChoice.js:49-58`）。
教程是纯阅读弹窗，按一下回车就没了。

```js
useEnterToConfirm: { type: Boolean, required: false, default: true }
created() {
  if (this.useEnterToConfirm) this.on$(GAME_EVENT.ENTER_PRESSED, this.doConfirm);
}
```

默认 true → 其余几十个弹窗行为零变化。**没有整体换成 `ModalWrapper`**，原因写在 §六。

### 2. 教程的阅读位置跨组件重建保留

`src/core/oreki-tutorial.js` 新增导出：

```js
export const TutorialReadingPosition = { chapterId: null };
```

`OrekiTutorialModal` 里：

- `data()` 先看有没有记录，有就用它，并把 `navigated` 置真（否则阶段轮询会把它抢回去）；
- `created()` 监听 `CLOSE_MODAL` → 标记 `closedByUser = true`；
- `beforeDestroy()` → `TutorialReadingPosition.chapterId = closedByUser ? null : chapter.id`。

区分「玩家主动关」与「被顶掉」的依据：**只有主动关闭会派发 `CLOSE_MODAL`**，
被顶掉走的是 `sortModalQueue` 改变 `current`，不派发。所以不需要额外字段。
不写 `player`（守住「本模块只读存档」），也不落 localStorage（刷新后应重新按阶段定位）。

### 3. 模板传 `:use-enter-to-confirm="false"`

## 六、为什么没整体换成 `ModalWrapper`（与 team-lead 建议的差异，请裁决）

你建议「这条都要改成 `ModalWrapper`（无 confirm 语义）」，我采纳了**语义目标**但没换实现，原因是布局：

- `ModalWrapperChoice` 根节点是 `.c-modal-message .l-modal-content--centered`；
- `ModalWrapper` 根节点是 `.c-modal__inner`。

教程是「左侧章节目录 + 右侧正文」的两栏布局（`.c-oreki-tut__layout`），宽度完全依赖前者的
`l-modal-content--centered` 约束。换成 `ModalWrapper` 后没有这层宽度约束，两栏会在窄屏上塌掉；
而 `OrekiTutorialStyles.js` 里 164 行样式没有一条依赖包裹层类名，反过来也说明**不能靠改样式救**。

所以最小改动是给 `ModalWrapperChoice` 加一个默认 true 的开关，只关掉 Enter。
如果你仍要求换包裹组件，我可以做，但需要同时给 `.c-oreki-tut__layout` 补 width/max-width
并在移动端宽度下实测——这是另一个量级的改动，想先听你的意见。

## 七、还没解决的（诚实标注）

1. **被顶掉这件事本身没消除**。成就说明仍会盖住教程，只是现在盖完之后能回到原章。
   要彻底不打断，需要一个「阅读态暂缓被动消息」的机制；`Modal.message.show` 在 core `modal.js` 里，
   而且它带 `props.callback`，直接丢弃会吞掉回调，所以我没有动。可选方案有两个：
   - (a) 教程打开期间把消息**排队**，关闭教程后依次补发；
   - (b) 给教程一个「独占期」，期间 `Modal.message.show` 只进队列不置顶。
   两条都要改 `modal.js`，**不在我确认过的写入范围里**，要不要做由你定。
2. `TUTORIAL_LEGACY_CHAPTERS` 的旧正文**其实没丢**，可从 `57ea0fb` 取出（详见下一份报告 §附）。
   team-lead 说「已经丢了」这个前提可以修正，但按你的裁定仍然不复原。
3. 本轮只测了「成就说明」这一种覆盖者。其它 priority ≥ 1 的弹窗（永恒/现实确认框）走同一机制，
   行为应当一致（组件销毁 → 重建 → 续读），但我没有逐个实测。
