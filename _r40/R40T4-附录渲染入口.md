## 4. 22 项逐条 + 「判据写错会怎么误报」

> 每条 PASS 后面那句是**这个断言的失败模式**：判据写偏时，它会在什么情况下仍然亮绿。

1. **目录底部有 7 篇附录入口（实际 7 条）**
   → 若把分组标题「附录（不参与主线进度）」也算进按钮集合，会数出 8 条、把「少一篇/多一个标题」判成 PASS。所以选择器是 `.c-oreki-tut__nav-btn--apx`，且额外读了文字前缀「附 」。
2. **附录 A 正文 2334 字符 / table=3 rows=82**
   → 若判据是「元素存在」（`!!document.querySelector(".c-oreki-tut__md")`），`v-html` 渲染出空串也会 PASS —— 上一轮已经吃过这个亏。这里断言的是 `innerText.trim().length`。
3. **附录 B 1793 字符 / 2 表 37 行**
   → 若只数 `table` 标签不数行，渲染器把「表格语法没识别、整段当文本」时 `table=0` 会失败，但如果整段被当文本仍能过长度阈值，就看不出表格丢了。所以长度与表格行数**两个都断**。
4. **附录 C 1097 字符 / 3 表 10 行**
   → 长度阈值 200 只能证明「不是空壳」，证明不了「内容对」。C 篇正文 1303 字符，渲染后 1097，差 206 字符正是被 `|` 与 `---` 吃掉的表格语法；若渲染器把 `---` 当分隔线渲染成功、却把表格当纯文本，长度会更高但 `table` 归零 —— 由第 5 条兜住。
5. **附录 D 1077 字符 / 3 表 44 行**
   → 中英对照表 44 行是「页签中英双写」的落地证据。判据若只查「含中文」，纯中文正文也能过，双写没落地都发现不了。
6. **附录 E 1948 字符 / 1 表 19 行**
   → 症状对照表只有 1 张，若判据写「表格数 ≥ 2」这条会假失败；写成「有表格就行」又会漏掉「表被拆成两段」的渲染 bug。
7. **附录 F 5648 字符 / 0 表**
   → 这是**反例保护**：如果判据统一要求「每篇都必须有表格」，F（纯段落）会被判失败，然后有人去给它硬塞一张表 —— 所以判据按篇设，不搞统一阈值。同时它验证 `auto: "automation"` 的聚合正文（18 章 `automation` 字段拼起来）确实渲染了。
8. **附录 G 2644 字符 / 3 表 21 行**
   → 若只断言 `table ≥ 1`，`apx_changes` 被截断成第一张表（15 行）也会 PASS，第二、三张表丢了看不出来。完整断言见第 9 条。
9. **`apx_changes` table=3 rows=21（≥15）**
   → 21 = 15（缩放）+ 2（速度）+ 4（没改的）。若判据写 `rows ≥ 15` 而渲染器把三张表合并成一张，仍是 21 行、仍 PASS，但结构塌了。所以同时断 `table=3`。
10. **附录 D 可滚动到 500px**
    → 若滚动容器选错（滚 `window` 而不是 `.c-oreki-tut__scroll`），`window.scrollY` 恒 0，这条会假失败；反过来如果断言写成「滚动不报错」，选了不存在的元素也不会报错，假 PASS。
11. **点 × 能关闭附录**
    → 只看 `open=false` 会被「队列里还有别的弹窗」骗：教程关了但 `current` 换成了 MessageModal，玩家看到的还是弹窗。所以同时读 `cur`。
12. **重开仍在附录 D**
    → 判据若只写「标题含『附录』」，重开落到附录 B/C 也会 PASS。必须比对完整标题「附录 D　中英界面对照」。
13. **重开后滚动位置保留（500 → 500）**
    → ±1 行 = ±32px 容差。若容差写成 ±200px，落到 D 篇另一段也会 PASS；写成 0 容差又会因为 `scrollTop` 取整在 499/500 之间抖动而假失败。
14. **从附录切回第 7 章**
    → 与第 16 条同一个陷阱：新生档自动跑起来后当前阶段**恰好**是第 7 章，若判据写死「等于第 7 章」，附录没清干净（`appendixIndex` 没置 -1）也能碰巧通过。所以第 16 条改成与 `getTutorialStartIndex()` 动态比对。
15. **章节点 × 关闭后重开按当前阶段定位**
    → 同上，判据是「实际 == 期望 == `getTutorialStartIndex()` 的返回值」，而不是字面写死章号。
16. **【模拟】教程被消息顶掉（`current=MessageModal`）**
    → 这条是**模拟**：人为把 priority 压回 0 制造「被顶掉」，用来验「回来时位置还在」。它不代表现状（现状 priority 4，顶不掉），不能混进「现在会被顶掉」的结论。
17. **【模拟】被打断回来后仍是第 7 章**
    → 同理。若判据写「标题不变」，从一个本就相同的标题出发永远为真；脚本里是「先跳到第 7 章 → 模拟销毁 → 重建」，比对的是重建后的 `index`。
18. **按 Esc 能关闭附录**
    → Esc 走 `Modal.hideAll()`，**不派发 CLOSE_MODAL**。若判据是「`closedByCloseEvent` 为真」，Esc 永远判失败；若判据是「`open=false`」而没读 `queue`，队列里残留也看不出。
19. **Esc 关闭后重开不粘旧附录**
    → 若 `beforeDestroy` 里无条件写 `chapterId = currentId`，这条会假失败（重开还在附录 D）；若完全不在 `beforeDestroy` 写，第 12 条会假失败。两条互为约束，只写一条都测不出「该记的记、该忘的忘」。
20. **Esc 关闭后重开滚动归零（0px）**
    → 元素未挂载时 `scrollTop` 读到 `-1`；若判据是 `!scrollTop`（falsy），`-1` 也会 PASS。这里显式断言 `=== 0`。

    → 两个选择器任写错一个都会恒为 0/恒为 false，从而恒 PASS。所以同时断两个不同结构，并且这一条与第 22 条（真渲染过 7 篇正文）成对读才有意义：**先证明附录真的渲染了，再证明它没带章节装饰**。

    → `page.on("pageerror")` 必须在 `goto` **之前**注册，否则首屏模块加载期的语法错误（上一轮的反引号事故就是这一层）会漏掉。脚本里注册在 `newPage()` 之后、`goto` 之前。

## 5. 测试方法陷阱

按你的要求把三个 + 我这轮新踩的两个都记下来，下次谁写同类脚本直接抄这一节。

1. **同帧赋值 `scrollTop` + 立刻触发关闭** → 读出 0。
   `box.scrollTop = 420; Modal.hide()` 在同一帧里，`scroll` 事件根本没派发，`@scroll` 处理器没跑，位置没写进 `TutorialReadingPosition`。**必须赋值后等 ≥ 400ms** 再关。
2. **没 drain 真成就消息就开测** → 教程只在队列里、压根没挂载。
   开跑 3 秒内成就 55 会弹一条 `Modal.message`（priority 3），此时再 `Modal.orekiTutorial.show()`，教程排在队列第二位，`document.querySelector(".c-oreki-tut")` 是 `null`，`scrollTop` 读到 `-1`。脚本里先 `Modal.hideAll()` 再开。
3. **合成消息与真成就 55 文案撞车** → 分不清「我插的测试消息」和「游戏自己弹的」。
   真成就 55 的文案含「1 分钟内完成了一次无限」，我一开始照抄了这句做断言，结果补发的到底是哪条说不清。改成测试消息固定前缀 `测试：`，用 `startsWith` 判。
4. **（本轮新踩）`beforeDestroy` 里读 `$refs.scroll.scrollTop` 得 0。**
   Vue 在 `beforeDestroy` 之前已经把 `$refs` 摘了，读到的是 0，不是「滚动到顶」。位置只能在 `@scroll` 过程中写入 `TutorialReadingPosition`，销毁时只做「要不要记」的判断。
5. **（本轮新踩）模板里用反引号拼字符串，会把外层的模板字符串提前闭合。**
   `{{ isAppendix ? \`附 ${…}\` : … }}` 在 HTML attribute 内的 JS 模板串里，浏览器报 `Unexpected identifier '附'`，`window.Modal` 整块不执行 → 所有验收脚本在 `openTutorial()` 崩掉。改成普通字符串拼接 `"附 " + (appendixIndex + 1) + " / " + appendices.length`。

1. **这些确认框只能由玩家点击触发，而教程打开时点不到底层按钮。**

2. **万一是自动化/程序路径把确认框排进来，它不会被吞，只会延后。**
   `[模拟]` 教程开着时执行 `Modal.eternity.show()` → `current` 仍是 `OrekiTutorialModal`、队列 `["OrekiTutorialModal#4","EternityModal#1"]`；点 × 关教程后 `current=EternityModal`、队列只剩它。确认框完整交回玩家，没有静默执行任何重置。
3. **反方向代价更大。** priority 若 ≤ 1，任何一次大坍缩确认、任何一条成就 55 文案都会把教程组件销毁（`PopupModal` 只渲染 `current`），重建时 `data()` 重跑、`index` 回落到当前阶段 —— 这正是 `c7d59f3` 里实测到的「跳到第 10 章，1.4 秒后被顶回第 7 章」。在「教程可能被销毁」与「确认框可能延后几秒」之间，选后者。

结论原话：**我判断可接受，依据是「确认框只能由玩家点击触发，教程打开时全屏遮罩挡住游戏 UI；程序路径排进来的确认框只会延后弹出、不会静默执行；反过来降 priority 会让教程被销毁」。** 不写成「我确认无风险」——第 2 条那个延后场景确实存在，只是后果可控。
