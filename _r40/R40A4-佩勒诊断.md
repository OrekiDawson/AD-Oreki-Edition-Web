## 0. 一句话结论

**判定：逻辑死锁（自动化缺一次合法动作），`0.7505` 只是它的数值症状，不是「数值墙」。**

> 本节结论里的每一个运行值都已在 `r40a4-pelle2`（781 s 进毁灭）里**实测**：`break=false`、`hasMaxedInterval=false`、
> `autobuyersOn=true`、`keepAutobuyers` 未买、`realityShards=0`、`am=1.7976931348623157e+308`、`totalAM=1e315.986`、`endState=0.750357` 恒定 185 条采样。
> 明细见 §7。

进入毁灭现实（`Pelle.isDoomed`）后，`player.break` 被现实现重置清成 `false`（`reality.js:633`），
而本作把它重新打开的两条原版路径**同时被切断**：

1. **自动路径**：`tryOpenBreakInfinityGate()` 里写着 `&& !Pelle.isDoomed`（`game.js:212`）⇒ 毁灭态永不调用 `breakInfinity()`；
2. **重置路径**：原版 `reality.js:750` 会在「毁灭态 + 已买 `keepAutobuyers` + BC 间隔拉满」时把 `player.break` 置回 true，
   但本作的 `driveDoomed()` **既不做 Armageddon 也不请求现实**（`_stopDoomedResets()` 还每帧关掉大坍缩/永恒自动器），
   于是这一行在整个毁灭阶段一次都不会执行。

`player.break === false` ⇒ `AntimatterDimensions.tick()` 每帧开头直接 `return`，并把反物质 `dropTo(Player.infinityGoal)`（`1.7976931348623157e308`），
同时产量按 `DC.E315` 封顶（`antimatter-dimension.js:580/609/662-663/682`）。
结果 `records.totalAntimatter` 最多到 ~1e315，`endState` 的天花板就锁死在 0.75 附近 —— **实测 0.7505 反解正好是 1e316.2**，与 1e315 的产量封顶同量级。

**再加一条把它钉成「死循环」而不是「慢」的事实**：`realityShards` 的产出是
`(10^(remnants^(1/7.5)·4) − 1)/1000`（`pelle.js:289-295`），`remnants` 只在 `armageddon()` 里增加（`:152-154`）。
`armageddon` 一次都没发生 ⇒ `remnants = 0` ⇒ **shards 每秒产出恒等于 0** ⇒
`keepAutobuyers`（5e6 shards，`pelle-upgrades.js:73-78`）永远买不上 ⇒ `reality.js:750` 永不开火 ⇒ `break` 永远是 false。
**没有任何「等久一点就会好」的可能** —— 这也是我把它判成「逻辑死锁」而不是「数值墙」的最后一块拼图。

到 1 需要 `E = 1000`（`OREKI_PELLE_END_TARGET_EXP = 1e3`，`game-end.js:61/63-70`），**中间差 684 个数量级**，靠等待、靠买佩勒升级、靠多跑几十分钟都不可能跨过去。

原版对照（这一点很关键，它说明**不是**「目标不可达」）：官方 `game-end.js` 的分母是 `log10(9e15) - 8.7`，
过线点 = **反物质指数 9e15**（`Decimal.MAX_VALUE`），比本作的 1e3 高 12 个数量级。
⇒ 原版毁灭态**必须**能突破 `1.8e308`，否则官方自己也通不了关。所以「Doomed 里永远到不了 E=1000」这个说法**不成立**，
真正的问题是**本作的自动化没有把原版那条 Break 的路径走完**。

## 2. `endState` 三要素（运行时取值，不是复述公式）

`src/core/celestials/pelle/game-end.js`：

```js
export const OREKI_PELLE_END_OFFSET = 1;          // :60
export const OREKI_PELLE_END_TARGET_EXP = 1e3;    // :61

get endState() {                                  // :63-70
  return Math.max((Math.log10(totalAntimatter.plus(1).log10() + 1) - OFFSET) /
    (Math.log10(TARGET_EXP + 1) - OFFSET) + this.additionalEnd, 0);
}
```

| 要素 | 取值 | 来源 |
|---|---|---|
| `OREKI_PELLE_END_OFFSET` | `1` | `game-end.js:60` |
| `OREKI_PELLE_END_TARGET_EXP` | `1e3` | `game-end.js:61` |
| 过线判据 | `log10(totalAM) ≥ 1000`（算式等价于 `E = TARGET`） | 分母对称化后的等价式，`game-end.js:44-59` 注释 |
| 实测 `endState` | `0.7505`（185 s 零变化） | `r40a3-fix2.jsonl` |
| 实测反解 `totalAM` | `1e316.2` | §1 E5 |
| 过线所需 `totalAM` | `1e1000` | 同上 |
| **差** | **684 个数量级** | — |

> **不要动 `TARGET_EXP`。** 把它从 1e3 降到 3e2 之类，等于把「通关」的定义改成「不用 Break 也能到」，
> 与 R40「真实通关，不伪造状态」直接冲突。这条只在「证明原版也到不了」时才成立，而 E12 已经把它证伪。

## 3. 反物质到底停在哪（数值侧）

| 量 | 实测/推导 | 说明 |
|---|---|---|
| `player.antimatter.exponent` | 308（恒定 185 s） | 即 `log10(AM) = 308`，`AM ≈ 1e308` |
| `Player.infinityGoal` | `1.7976931348623157e308` | `player.js:986-988`，无毁灭态特例 |

| `!player.break` 时 clamp | `Currency.antimatter.dropTo(Player.infinityGoal)` | `antimatter-dimension.js:682` |

**这一栏最容易误判成「数值墙」**：amE 一动不动看起来像公式到了尽头。

说明**产量在算、只是每帧被丢掉**——`return` 发生在累加之前（`:663` 在 `:669` 的 `produceCurrency` 之前）。
真正的「数值墙」形态应该是产量为 0（维度链断裂），这里不是。

### 7.2.1 口径复核（回答「是不是 JS Number 截断」）

| 口径 | 实测 | 结论 |

⇒ 这是 `dropTo(Player.infinityGoal)` 的**精确落点**，不是数值精度 bug。不需要去查 `Number.MAX_VALUE` 的换算代码。

### 7.4 定性（四选一，带证据）

| 候选 | 判定 | 证据 |
|---|---|---|
| 节流太久 | **否** | `doomMs` 每 ≤100 ms 刷新（`DOOM_BUY_MS=100`）；`_lastError` 全程空 |
| 自动化未接管 | **是（表象）** | `driveDoomed()` 只做 maxAll/升维/星系/买升级，从不 Armageddon、从不请求现实（`oreki-endgame-automation.js:440-486`） |

**最终判定：逻辑死锁。** 缺的那一步是原版毁灭态的「大灾变循环」（`Armageddon → remnants → shards → keepAutobuyers → 下一次现实重置恢复 break`），

### 8.2 `hasMaxedInterval` 为什么会掉（静态链）

1. `Pelle.initializeRun()` → `armageddon(false)` → `finishProcessReality({reset:true})`（`pelle.js:83/155`）；
2. 现实重置 → `Autobuyers.reset()`（`autobuyers/autobuyers.js:155`，挂在 `REALITY_RESET_AFTER`）；
3. `UpgradeableAutobuyerState.reset()`（`autobuyers/autobuyer.js:185-190`）只在
   `EternityMilestone.keepAutobuyers.isReached || PelleUpgrade.keepAutobuyers.canBeApplied` 时早退，
   否则 `data.interval = baseInterval`（150000）；
4. 末日同时清零永恒次数（`reality.js:643`，除非已买 `eternitiesNoReset`），
   而 `keepAutobuyers` 里程碑只要 **2 次永恒**（`secret-formula/eternity/eternity-milestones.js:7-11`）⇒ 进毁灭那一刻 `isReached` 翻假；
5. interval 回 150000 ⇒ `hasMaxedInterval = false`。**不买 Pelle 的 `keepAutobuyers`，每次末日都会再清一次。**

### 8.3 还有**第三个** Doomed 守卫（之前没人注意）

`src/core/oreki-break-infinity-gate.js:73`：`active()` 里写着 `if (Pelle.isDoomed) return false;`。
这个闸门本来就是本 MOD 为「间隔从 150000 拉到 100 要 32767 IP、而全仓只有 UI 按钮会买」造的自动化，
做的正是 `upgradeInterval(false)`（游戏真实购买路径、真实扣费）+ 一次性补足 32767 IP。
**它被 Doomed 排除，正好把毁灭态里唯一能重新拉满间隔的自动化掐掉了。**

⇒ 完整死路：末日后 interval 回 150000 → 闸门在 Doomed 不工作 → `hasMaxedInterval` 永远 false
（毁灭态里 1 IP/次坍缩，32767 IP 不可达）→ `breakInfinity()` 永在第一行退出 →
`keepAutobuyers`（5e6 shards）也买不上（shards 恒 0，E11）→ 闭环。

### 8.4 两个候选（都只动本 MOD 自己加的守卫）

**A（最小）**：删 `oreki-break-infinity-gate.js:73` 的 `if (Pelle.isDoomed) return false;` + 删 `game.js:212` 的 `&& !Pelle.isDoomed`。

**B（更「原版」但更慢）**：`driveDoomed()` 补末日循环 → `remnants > 0` → shards > 0 → 买 `keepAutobuyers` →
