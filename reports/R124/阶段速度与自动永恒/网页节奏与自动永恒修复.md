# R124 Web 阶段速度与自动永恒修复

## 结论

本 PR 只处理 R124 Web 主线中仍未被 #112 替代的两类 P1：

1. 新档阶段速度没有持久化阶段归属，且旧默认 3000×、TT ×500、现实额外 +4 会压缩
   0～75 分钟的无限与永恒阶段。
2. 永恒结算会把原版自动永恒开关复位为 `false`，旧归属判定把它误认成玩家手动关闭；
   EC 中的永恒重置又被 `active=false` 和全局 EP 门槛挡住，可能出现目标已达成但挑战长期不结算。

挑战“进入即完成”、C/IC/EC 写完成位与教程中的旧即时完成说明已由 #112 进入主线，
本 PR 不重复移植或改写那部分结算语义。

## 修改

- 新档阶段速度改为 Break 前 `1000×`、Break 后 `1800×`、Reality 后 `3000×`。
- 阶段托管状态与上次阶段独立持久化；刷新不重放阶段默认值，动态升档后的倍率不会被静默打回。
- 玩家手动倍率优先；“恢复默认”重新启用当前阶段的托管速度。
- 设置页提示使用响应式镜像，不再缓存普通对象属性。
- TT 购买收益恢复原版 `×1`；现实模拟移除额外的 `+4` 次模拟现实。
- 自动永恒开关归属同时观察本现实计时、本永恒计时、永恒计数和 Reality 计数。
- UI 与热键切换会显式记录玩家意图；永恒计时回退不得覆盖同周期内的手动关闭。
- EC 中仅放行“原版目标已满足后的真实永恒结算”，不绕过 `canBeCompleted`。
- 托管自动器补上无限维度组与 ID1～ID8，Eternity/Reality reset 后下一次调度 Tick 恢复。
- 教程同步阶段速度与新档节奏说明，并由源码 JSON 重新生成浏览器模块。
