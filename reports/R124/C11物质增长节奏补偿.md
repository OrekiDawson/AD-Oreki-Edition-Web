# Web C11 物质增长节奏补偿

## 问题与根因

Android 从 C9 原版结算档继续到 C11 后，约 40 分钟仍为 `current=11`、
`dimensionBoosts=2`、`galaxies=0`，远超预期的挑战阶段时长。

Web 冻结基线 `src/core/normal-challenges.js` 在 C11/IC6 中明确使用：

```text
diff / getGlobalSpeedFactor() / 20
```

因此 MOD 的全局阶段速度被完整抵消。C11 的物质增长实际仍接近未加速速度，
这不是挑战完成位或自动购买器完全未运行的问题。

## 修复

新增 `c11MatterGrowthPower(diff, speedFactor)`：

```text
diff / sqrt(speedFactor) / 20
```

F=1 时保持原版；F=1800 时保留有界加速，同时不改变原版
`Currency.matter.bumpTo(1)`、`softReset(...)`、`Player.canCrunch` 与挑战目标。

## 验证

- Playwright Pixel 7：`challenge-real-settlement.spec.mjs` 5/5 PASS。
- `check_game_pace.mjs`：PASS，锁定 F=1 与 `sqrt(F)` 补偿路径。
- `check_eternity_gate.mjs`：219/219 PASS。
- `node --check` 与 `git diff --check`：PASS。
- 定向公式：F=1 时功率为 `diff/20`；F=1800 时相对原版补偿
  `sqrt(1800)`，F=0/非法值安全回落到 1。

## 边界

完整新档 PACING、ENDGAME、POST-ENDGAME STABILITY 与 SAVE COMPATIBILITY
仍为 `NOT RUN`。本 PR 只修复已证实的 C11 慢节奏根因，不替代完整发布门禁。
