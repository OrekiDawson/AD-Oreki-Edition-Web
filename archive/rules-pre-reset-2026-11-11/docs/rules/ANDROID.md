# Android 实现与分析

本文件是 Web 仓库涉及 Android 对照、基线和移动端验收时的当前规则入口。

## 1. 对照边界

### 1.1

Android 与 Web 保持 MOD 核心机制、资源语义、阶段条件、自动化目标和玩家可见结果一致；不要求 Web 复制 Android 的 Kotlin、DEX 或底层实现。

### 1.2

Android 业务修改必须遵守 Android 仓的 Kotlin-only、基线和 ABI 规则。Web 仓只记录跨端契约，不复制 Android 的完整分析正文。

## 2. 移动端验收

### 2.1

需要 Android Chrome 行为验收时使用真实 Android Chrome 和当前移动端视口；桌面窗口或 Headless 结果不能冒充移动端证据。

### 2.2

GUI 验收记录浏览器、设备、页面、存档、操作步骤和实际结果；关键操作保留前后截图，状态变化必须在真实屏幕上可见。

### 2.3

Android 与 Web 共用 AVD 或观测资源时严格串行；其他 Agent 只能读取已保存证据，不得并发向设备发输入。

## 3. 存档与构建

### 3.1

本地测试隔离浏览器 profile 和真实存档，保护 `_saves/`。修改计时或倍率时覆盖默认值和至少一个中间值；未覆盖范围如实记录。

### 3.2

优先使用现有依赖和离线工具链；缺少必要包时才补齐，不擅自升级或修改无关依赖。

## 4. 游戏行为

### 4.1

导航沿用原版结构，移动端保持触控和可读性。自动购买器的配置调整不得强制打开玩家关闭的购买器，不得覆盖无关手动设置。

### 4.2

无限阶段隐藏永恒层内容；永恒阶段才显示永恒次数和永恒点数；现实内容只能在真实现实结算后显示。

## 5. Web 发布

### 5.1

Pages 只在必要测试通过并获得当前交付授权后部署；必须检查实际线上页面、资源和关键功能。

### 5.2

Android 阻塞不自动阻止独立 Web 交付，但两端证据不得互相冒充。结果区分 `PASS`、`FAIL`、`BLOCKED` 和 `NOT RUN`。
